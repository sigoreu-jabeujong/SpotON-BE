# 전체 시스템 기능 점검 결과

- 점검일: 2026-11-12 (KST)
- 관련 이슈: [#78](https://github.com/sigoreu-jabeujong/SpotON-BE/issues/78)
- 기준: BE `45a6bbf`, FE `21ec13fb59d1eed456c150b2c99300d9fe755d5a`(검사 당시 원격 develop과 일치)
- 설계·Claude 실제 검토·최종 결정: [설계 문서](designs/feat78-system-functional-audit.md)

**전체 시스템 정상 판정은 보류합니다.** BE의 기존 일반/격리 검사와 실데이터 조회·실모델 검사는 통과했지만, 실제 FE 연결에서 수정할 문제5종을 재현했습니다. 지도는 JavaScript 키 설정 대기이고 일반음식점 원천 API는 응답 지연을 관측했습니다. 성공한 검사와 미구현/외부 차단을 구분합니다.

## 1. 검사 방법

각 기능을 정상·빈 결과·잘못된 입력·실패·다음 기능 연결 순서로 확인했습니다. 실제 개발 DB는 기존 guard와 읽기 전용 세션을 사용했고, 적재/rollback/마이그레이션의 파괴적 검사는 별도 포트의 일회용 PostGIS에서만 실행했습니다. 이번 감사에서 실제 .env/Docker·원본/앱 의존성·FE 추적 파일은 바꾸지 않았습니다.

FE lint/build와 headless Chrome 데스크톱1440×1100 검사를 수행했습니다. VITE_USE_MOCK=false와 테스트용 API 주소/CORS는 프로세스 환경·Settings 복사본에만 적용했습니다. 브라우저용 BE는 실제 LLM 키를 제거하고 모의 공급자·외부 모델 송신 차단을 강제했습니다. 실제 LLM은 별도의 제한된 검사로 분리했습니다. trace/video/HAR/스크린샷·원문 주소/좌표/키/응답은 보고서에 저장하지 않았습니다.

구체적인 파일·재현·계약·완료 기준은 [FE 수정 요청 보고서](fe-system-audit-request.md)에 기록했습니다. 모든 합성 경계 응답은 BE ApiResponse[StoreHistory] 스키마 검증을 통과한 뒤 브라우저에 주입했습니다. 성공 응답을 파손시켜 만든 오류가 아닙니다. 실제 단순 이력5행은 정상 렌더됐습니다.

**최초 감사에서는 BE 계약 위반으로 확정한 앱 결함을 발견하지 못했습니다.** 이후 요청서 재점검에서는 실제 동시 조회500을 관측했으므로 현재 상태는 아래6절을 함께 따릅니다. 일반음식점 외부 응답 지연, 테스트 코드의 CATEGORY_REQUIRED 기대값/셸 인코딩 보정, FE의 유효 응답 처리 결함을 구분했습니다. BE API를 바꾸거나 승인 없이 FE를 수정하지 않았습니다. 사용자 지시에 따라 FE 담당자에게 보고서로 요청하며 담당자 수정 결과 확인 전 전체 정상으로 표시하지 않습니다.

## 5. 남은 상태

- 테스트 도메인 등록 후 SDK·기본 마커/표/반경/정보창 연동은 통과했습니다. 원천 간 같은 관리번호의 선택/정보창 오류는 FE 수정 대기입니다(7절).
- FE 담당자의 F1~F5 수정·타입/계약/CLAUDE.md 반영·실제 화면 재검증.
- 일반음식점 원천 API의 지연/가용성 재확인. 키 오류/활용승인 실패로 확인된 것은 아닙니다.
- 일반음식점은 최소1행/30초의 별도 진단에서도 ReadTimeout이었습니다. 첫15초 probe·기존설정20초 probe·최소1행30초 진단의 총3회 이후 추가 호출을 중단했습니다. 휴게음식점은 기존설정으로3.91초에100행200이었으므로 전체키가 잘못됐다고 단정하지 않았습니다. 불확실한 상태에서 앱 timeout이나 수집 규칙을 임의 변경하지 않았습니다.
- 기존 브랜드57 활용승인, 공식/조건부 수치 활성화의 경계/기간 의미, 지원링크 맞춤정렬, AI추가문맥/자유문장 의미검증 전체, 로그30일 보관/삭제는 미구현/미확정입니다. pending이 올바르게 반환되는 것과 기능 구현 완료를 구분합니다.
- 운영부하/장기 안정성/분산한도·다중브라우저/모바일·보안 전체·배포/최종제출은 이번 점검으로 완료하지 않았습니다.

독립 HTTP 요청 사이의 원자적 snapshot은 보장하지 않습니다. 이번 실제 검증은 다른 writer가 없는 개발 DB 기준이며, 실제 외부 공급자의 다음 응답과 향후 가용성을 보장하지 않습니다.
