# 동일 지표의 양면 해석 설계·검토

2026-11-17. 같은 관측값을 영업 조건에 따라 이점과 유의점으로 설명한다. 유의점은 관측된 불리한 비교와 조건부 운영 부담을 구별한다. GPT가 직접 문장을 작성하며 서버는 비교 가능한 근거와 역할별 필수 인용 범위를 전달한다.

| 자료 | 이점 | 조건부 유의점 | 금지하는 확대 해석 |
| --- | --- | --- | --- |
| 같은 행정동·관측일의 주간/야간 생활인구 | 더 큰 시간대의 체류 특성을 활용할 서비스 | 상대적으로 작은 시간대 중심 영업을 계획한다면 상품·영업시간 전략 필요 | 실제 고객 부족, 절대적 수요 부족, 유흥 상권 확정 |

## 구현 계약

- 기존 adverse_signals는 관측된 불리한 비교로 유지한다. conditional_tradeoffs는 영업 조건과 상대 비교 방향을 제공한다. 최종 문장은 미리 작성하지 않는다.
- 행정동은 검색 위치 포함 행정동을 우선하고, 동일 식별 범위의 주야 쌍만 비교한다. 행정동 비교가 없을 때만 동일 집단 공개 격자 쌍을 대체 관점으로 사용한다. 서로 다른 지역/시점/집단/단위를 섞지 않는다.
- 동일 값, 결측, 음수, 유효하지 않은 상태, 표시값이 같은 반올림 자료에서는 방향을 만들지 않는다. 격자 야간 비중은 원천이 제공한 값만 전달하고 100에서 빼서 새 수치를 만들지 않는다.
- 주야 비교가 존재하면 이점과 유의점 각각에 해당 쌍을 인용한 항목을 최소 하나 포함한다. 기존 불리한 비교가 있으면 유의점에 그 비교 항목도 최소 하나 포함한다. 상단 각 카드 최대 4개로 제한하고 내용 중복을 줄인다.
- 모든 유의점 항목은 관측 비교 또는 허용된 조건부 근거를 완전히 인용해야 한다. 이점·유의점의 설명이 서로 모순되지 않도록 어떤 영업 조건인지 적는다.
- 수치 해석은 수치→가능한 특성→운영상 시사점 흐름을 유지한다. 공통 자료 한계·현장 확인 문구는 기존 ⓘ 팝오버에 유지한다. 계약 전 확인사항과 3회 모델 호출 계약은 유지한다.
- 프롬프트 버전 및 FE 해석 캐시 키를 변경한다. 응답 스키마/모델/키/기본 지표 계산은 변경하지 않는다.

## Codex 설계 검토

- 단순한 ‘모든 장점에 반대 단점 생성’은 비교 근거가 없는 부정적 결론을 만들므로 채택하지 않았다.
- 야간 > 주간은 같은 행정동 내 시간대 비교다. 서울 평균보다 주간이 낮다는 뜻이 아니므로 조건을 ‘주간 중심 영업을 계획한다면’으로 한정한다.
- 개업과 폐업은 기록 흐름이며 생존 코호트가 아니다. 경쟁 가능성은 신규 진입자 관점으로 한정하고 실현된 경쟁 강도로 확정하지 않는다.
- 수치·단위·근거 인용 및 필수 항목 누락은 서버 검증한다. 조건부 표현의 의미적 정확성 전체를 기계 검증했다고 주장하지 않는다. 실제 생성 표본을 양방향으로 검토한다.
- 검증 범위: 주야 양방향/동률/결측/시점 불일치/지역 불일치/반올림 동률, 격자 대체, 기존 불리한 비교와 시간대 관점 공존, 근거 누락 거부, 실제 API 및 팝오버·체크리스트·PDF 유지.

## 구현 검증

- BE 관련 테스트 104개 통과, Ruff 및 mypy 통과. FE lint, 결과 컴포넌트 테스트, 운영 빌드 통과.
- 운영과 같은 GPT 모델로 3개 역할을 생성하여 모두 근거·수치 검증 통과(이점 4개, 유의점 2개, 요약 6개).
- 야간 79,137.3명 > 주간 70,031.9명 표본에서 이점은 저녁 시간대 서비스, 유의점은 ‘주간 중심 영업을 계획한다면’이라는 조건과 낮 시간대 상품·유입 전략을 작성했다.
- 신규 개업 47건·폐업 30건·동종업체 408개 표본에서 유의점은 신규 공급·기존 업체와 구별되는 포지셔닝으로 통합했다. 임의의 과밀·임대료·매출 예측은 추가하지 않았다.
