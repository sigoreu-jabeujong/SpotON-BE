# 생활인구 원천 검증과 주야간 계산 준비

- 확인일: 2026-11-14 / 이슈 [#115](https://github.com/sigoreu-jabeujong/SpotON-BE/issues/115).
- 최신 결론: **전수 무결성·현재 격자의 코드/도형 정합은 확인했다. 별도 게시된00~02시 공식 행정동 집계894건도 일치했다. 한 격자 안의 행정동 간 가산성·행 부재 원인·공식 관측일별 적용 보증은 확정하지 못해 공개 인구 pending을 유지한다.** 항목별 최신 판정은7절을 따른다.
- 2026-11-14 사용자는 별도 공식 답변이 아직 없으며 문의 초안으로 진행하라고 답했다. 아래 문의는 제출 전 초안이고 실제 문의·회신 기록이 아니다.
- 1~6절은PR #116의 문서/metadata 검토다. 이후 사용자가 세 쟁점의 직접 테스트와 판단을 요청해7절의 원자료·DB 전수 검사 및 공식 집계 교차 검증을 추가했다. 각 절의 검사 범위를 섞지 않는다.

전체 PDF를 새로 전수 검토하거나 원본 인구 ZIP을 재수집·재적재하지 않았다. 로컬 DB 조회는 metadata이며 전체 내용 hash 재검사·새 반경 조사·인구 합산은 수행하지 않았다. Render DB·설정·공개 API·FE는 변경하지 않는다.

공식 웹 조회에서 장기외국인 페이지는 첫 조회에 지연103을 반환했으나 다음 조회는 데이터 설명과 파일 목록을 정상 반환했다. 이 오류를 자료 미제공이나 인증 실패로 해석하지 않는다.

## 3. 확인된 사실과 남은 질문

### 3.1 시간과 표시 단위

활용 매뉴얼 PDF3쪽은 시간 코드00~23에 대응하는 각1시간 구간과 그 시간에 가장 오래 머문 격자에 인구를 배정하는 설명을 제공한다. 같은 사람의 서로 다른 시간 관측이 존재할 수 있으므로 24시간 합을 하루 고유 방문자 수로 표시하지 않는다. 공식 안내도 통신·공공데이터로 추계한 시간·공간 인구임을 설명한다. [공식 설명](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)

SpotON은 사용자 결정대로 주간06:00~18:00미만(06~17), 야간00~05와18~23으로 구분한다. 2026-11-14 [공식 홈페이지 상단 현황](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)의 주간09시~18시 산술평균·야간19시~08시 산술평균 안내와 구분해 **SpotON 기준**이라고 표시한다. 홈페이지의 경계를 임의로 미만 구간으로 다시 해석하지 않는다. SpotON은 같은 관측일의 두 구간이며 전날 밤부터 다음날 아침까지의 연속 체류를 분석하는 지표가 아니다.

### 3.2 다른 행정동 행의 합산: 미확정

정의서가 행정동을 key로 두고 활용 매뉴얼 PDF9/11쪽의 예제도 행정동을 보존한다는 점은 확인했다. 이는 `(date,hour,grid)`만으로 행을 중복 제거하면 안 된다는 근거다. 하지만 서로 다른 행정동의 값이 겹치지 않는 부분값인지, 모든 필요한 행정동 구성요소가 파일에 있는지는 이 확인 범위에서 입증하지 못했다. 이후 직접 검사 결과는7.2절을 따른다.

시각별1인1격자라는 추계 원칙은 제공 CSV의 모든 행정동 행이 빠짐없이 중복 없이 구성됐다는 증거와 다르다. 공급기관의 합산 규칙과 기대 구성 근거가 있어야 원천 행을 격자별 시간 총계로 만들 수 있다.

### 3.3 없는 행과 비공개: 의미를 구분

공식 원천은 소규모 값을 `*`로 비공개 처리한다고 안내한다. 2026-11-14 홈페이지 유의사항의3명 미만과 개별 데이터 설명의3명 이하처럼 임계값 표현 차이도 있으므로 숫자에서 마스킹 여부를 추측하지 않고 원문 마커를 보존한다. [공식 유의사항](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do), [내국인 원천 설명](https://data.seoul.go.kr/dataList/OA-22784/S/1/datasetView.do)

활용 매뉴얼 PDF9쪽의 예제에는 비공개 값을 특정 숫자로 대체하는 코드가 있지만, SpotON은 사용자 결정대로 이를 적용하지 않는다. 원본 숫자0만 observed/0, `*`는 suppressed/null, 실제 빈 셀은 missing/null, 행 부재는 no_data로 구분한다. 이것은 [#53 적재](designs/feat53-living-population-import.md)·[#90 정책/로그](designs/feat90-population-quality-logs.md)의 기존 처리 정책이며, 행이 없어진 공급기관의 사유가 확인됐다는 뜻이 아니다.

격자에 숫자 행이 있더라도 다른 행정동 구성요소가 누락됐는지는 별도 문제다. 알려진 숫자만 SQL SUM으로 더해 완전한 시간 총계라고 표시하지 않는다.

### 3.4 현재 SHP와2026-11-07 관측의 대응: 미확정

활용 매뉴얼 PDF5쪽은 국가표준격자 코드와 좌하단/중심점 좌표의 관계를 설명한다. 이 정의와 현재 SHP/DB hash 일치는 좌표 체계와 사용 파일을 식별하는 근거다. 해당 SHP의 날짜별 제공 범위·수정 이력·특정 관측일의 모든 코드 대응까지 확정하지는 않는다.

기존 #53 검증에서 관측의 격자1개·비공개24행이 SHP에 매칭되지 않았다. PR #116의 metadata 조회에서는 그 원본 관측을 새로 전수 대조하지 않았으며, 이후 직접 전수 대조는7.4절에 추가했다. 가짜 좌표를 만들지 않고 기존 unlocated 보존·공간 집계 제외 정책을 유지한다. 공급기관의 관측일별 격자 적용 범위와 예외 처리가 필요하다. [기존 적재 근거](designs/feat53-living-population-import.md)

## 4. 내부 계산 계약

[계산 모듈](../app/analysis/day_night.py)은 이미 동일 관측일·공간·모집단으로 검증한 시간별 총계24개를 향후 입력받기 위한 산술 기반이다. 현재 서비스에서는 호출하지 않는다. 이 함수가 원천 행의 합산·행정동 구성·관측일·격자 적용을 검증하는 것은 아니다.

입력은00~23 순서의 Decimal/None tuple24개이며 숫자는0이상·1e15미만·표현상 소수5자리 이하다. 이 범위는 현재 내부 입력 계약이고 향후 실제 총계 타입은 별도 검토한다. None은 상위에서 해당 시간 총계를 제공할 수 없다는 표시이며 원래 결측·비공개·행 부재의 원인과 provenance는 상위가 보존한다. 상위는 비공개·셀 결측·행 부재를0으로 바꾸지 않고 None으로 전달해야 한다.

```text
D = P[6] + ... + P[17]
N = P[0] + ... + P[5] + P[18] + ... + P[23]
주간 비중 = D * 100 / (D + N)
야간 비중 = 100 - 표시한 주간 비중
주간/야간 평균 = D / 12, N / 12
주야간 배수 = D / N
```

비중만 최종 소수1자리 HALF_UP으로 표시한다. 평균과 배수는50자리 Decimal 문맥의 결과이며 최종 표시 반올림은 소비자가 정한다. D/N과 비중(%)은 서로 다른 값이다. D·N은 시간별 추정치를 누적한 값이고 인원이나 일일 고유 방문자 수로 표시하지 않는다. 표시0.0%만으로 실제 인구0을 판정하지 않는다.

| 입력 | 내부 상태 | 합계·평균 | 비중 | 배수 |
|---|---|---|---|---|
| 정상24시간, D+N>0,N>0 | calculated | 산술 결과 | 계산 | 계산 |
| 정상24시간, D>0,N=0 | calculated | 산술 결과 | 100%/0% | null |
| 정상24시간, D=N=0 | zero_total | 입력 합계0, 상위가 관측0을 전달했다는 전제 | null | null |
| None이 하나 이상 | incomplete | 전부 null | null | null |
| 잘못된 길이/타입/값 | 고정 ValueError | 결과 없음 | 결과 없음 | 결과 없음 |

calculated는 산술 성공만 뜻한다. 공개 API의 fact/verified와 연결하지 않는다. 모든 입력을 검사한 뒤 None을 판정하며, 잘못된 값이 있으면 incomplete로 숨기지 않는다. 원본 값·식별정보를 오류나 repr에 넣지 않는다. 새 Context로 전역 Decimal의 precision/rounding/traps/Emax/Emin/clamp와 분리한다.

## 5. 제공기관 문의 초안 — 미제출

제출 경로는 [서울시 생활인구 안내의 문의하기](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)를 사용한다. 실제 제출·기관 회신·적용 승인으로 표시하지 않는다.

**제목: 서울 생활인구250m의 행정동별 행 합산·미제공 행·격자 적용 범위 확인 요청**

서울 생활인구 내국인(OA-22784), 장기외국인(OA-22785), 단기외국인(OA-22786)의2026-11-07 일별 자료를 이용하려고 합니다. 현재 안내 페이지의 정의서·추계 매뉴얼·활용 매뉴얼·250m EPSG5179 SHP를 함께 확인했습니다. 아래 세 항목의 공식 처리 기준과 근거 문서 또는 버전을 부탁드립니다.

1. 동일 원천·일자·시각·CELL_ID에 서로 다른 H_DNG_CD 행이 여러 개 있을 때, SPOP은 서로 겹치지 않는 부분값인가요? 해당 행들을 모두 합산하면 그 격자의 시간별 생활인구 총계가 되나요? 기대하는 행정동 구성과 누락 여부를 확인할 공식 매핑이나 규칙이 있나요?
2. 특정 원천·시각·격자·행정동 조합의 행이 CSV에 없을 때,0명·비공개 생략·측정/추계 불가·비대상 중 어떤 의미인가요? 행이 제공되는 조건과 누락 검증 기준, 숫자 행만으로 구성 완전성을 확인할 수 있는지 안내 부탁드립니다.
3. 현재 안내 페이지의250m EPSG5179 SHP(infId=DOWNLOAD,infSeq=4,seq=37)가2026-11-07 관측의 공간 대응 파일이 맞나요? 적용 기간·버전 이력과 원천 격자가 SHP에 없는 경우의 공식 처리 방법 또는 보완 파일을 부탁드립니다. 현재 사용 ZIP SHA256은 `5f7f95db30f1d4a433d9905b281c3fb95b59cd8200985512a897326208bf525e`입니다.

비공개 값이나 원본 관측값을 문의에 첨부할 필요는 없으며, 격자 예외 사례의 식별 정보가 필요하면 기관이 안내한 전달 경로와 범위를 먼저 확인합니다.

## 6. 공개 연결을 재개할 조건

1. 세 항목의 공식 근거와 관측일별 적용 범위를 확보해 검증 기록으로 남긴다. 사용자 선택 정책이나 파일 hash 일치만으로 이를 대체하지 않는다.
2. 동일 반경의 격자·원천·행정동 구성과 시간별 완전성을 검증한다. 비공개·셀 결측·행 부재·미좌표를 보존하고 실제0과 구분한다.
3. 인허가 적용일과 별도로 인구 관측일을 반환하고, 미래 관측·서로 다른 날짜/모집단의 혼합을 막는 버전 선택을 구현한다. 이번에는 자동 날짜 선택을 구현하지 않았다.
4. activity/Risk의 typed 인구 응답·AI 범위·캐시/출처·FE 표시 계약을 함께 설계하고 실제 반경·날짜·상태 검사를 거쳐 연결한다. 이때까지 현재 인구 pending을 유지한다.

이번 구현·검토·검사 결과는 [#115 설계](designs/feat115-population-time-basis.md)에 기록한다. #115는 공식 근거와 공개 연결 후속 추적용으로 열어 둔다.

## 7. 세 쟁점의 직접 실증 검증 (2026-11-14 추가)

### 7.1 실행 범위와 무결성

기존 manifest의2026-11-07 내국인253,400행·장기외국인137,137행·단기외국인141,385행, 합계531,922행을 원본 ZIP부터 전수 재검사했다. 네 원본 ZIP SHA256을 실행 전후 대조하고 안전 parser의 헤더·날짜·시간·값 문법·행 수 검증을 통과했다. 완전키(source,date,hour,admin,grid) 중복은 세 원천 모두0건이다. 비공개 값을 숫자로 대체하거나 세부 값으로 복원하지 않았다.

별도 로컬 READ ONLY REPEATABLE READ 세션에서 **관측531,922행의 전체 저장 내용 지문**과 원자료 지문, **격자10,125행의 속성·geometry EWKB 전체 지문**을 대조해 일치했다. 관측 비교는 모든 저장 행을 스트리밍해 재계산했으며 metadata만 읽은 검사가 아니다. 행별 canonical JSON→SHA256과 C/UTF8 키 순서·원천 순서를 기존 적재 규칙과 동일하게 적용했다. geometry는 NDR EWKB로 비교했다.

같은 변환 코드의 일치만으로 공간을 판정하지 않도록 국가표준 코드의 독립 산식·원본5179 사각형·DB4326 도형의5179 역변환을 추가 대조했다. DB 세션만 SQL60초/lock5초로 제한했고 API 설정은 그대로다. DML/DDL/재적재/VACUUM·Render/FE 변경은 없으며 head0011·spatial_compatibility=unverified·grid_as_of=null을 유지했다.

### 7.2 쟁점1: 다른 행정동 행을 합산하면 중복인가?

**판정: 전체 프로필 복제 가설에는 반례를 확인했다. 한 격자 안에서 다른 행정동 행을 합산해도 중복이 없는지(가산성)는 확정 불가다. 개인 단위 비중복도 집계 자료로 확정할 수 없다.** 행정동 차원을 보존하고 자료를 임의로 중복 제거하지 않는 기존 정책을 유지한다.

| 검사 | 내국인 | 장기외국인 | 단기외국인 |
|---|---:|---:|---:|
| 복수 행정동의(source,hour,grid) 그룹 | 44,292 | 15,492 | 15,576 |
| 해당 그룹 중 총계가 전부 공개인 그룹 | 39,712 | 12,059 | 9,847 |
| 그중 행정동별 총계가 서로 다른 그룹 | 39,711 | 12,053 | 9,836 |
| 비교 가능한 행정동 프로필 쌍 | 38,770 | 12,255 | 7,229 |
| 총계·모든 상세 셀의 정규화 프로필 동일 쌍 | 0 | 2 | 0 |
| 비공개/정보 부족으로 프로필 쌍 비교 제외 | 14,620 | 4,963 | 10,223 |

프로필 비교는 총계가 공개 양수이고 총계를 포함한 숫자 셀이2개 이상인 행끼리만 했다. 원천은 서로 섞지 않고 같은 격자·시간의 다른 행정동을 비교했다. 숫자는 Decimal 소수5자리로 정규화하고 비공개·빈 셀 마커는 그대로 비교했다. 한 행의 세부 합으로 총계를 복원하지 않았다.

우연히 같은 값이 나오는 기준선도 확인했다. 같은 원천·시간·행정동 쌍 안에서 다른 격자의 오른쪽 프로필을100회 회전시켰다(seed11520261114, 원천별+0/+1/+2). 회전 가능한 비교 쌍은30,263/6,055/3,217개다. 그 안에서 관측된 동일 프로필 쌍은0/2/0개, 회전 기준선 평균은0.57/2.47/0개였다. 동일 프로필의 집중 복제를 뒷받침하지 않으며, 이 기준선은 통계적 유의성 검정이나 개인 중복률 추정이 아니다. 값이 달라도 일부 사람이 겹칠 가능성까지 배제하지는 못한다.

별도 게시된 공식 행정동 집계와도 대조했다. 대상은 [내국인 OA-23016](https://data.seoul.go.kr/dataList/OA-23016/S/1/datasetView.do), [장기외국인 OA-23017](https://data.seoul.go.kr/dataList/OA-23017/S/1/datasetView.do), [단기외국인 OA-23018](https://data.seoul.go.kr/dataList/OA-23018/S/1/datasetView.do)다. 각 공식 Sheet의 정상 조회 방식으로 YMD=20261107을 검색하고 기본 첫 페이지 최대1,000행만 받았다. 서버 제공 숨김 조건·접근 범위는 유지했다. AXGrid 응답의 문자열/키/마지막 쉼표를 안전하게 정규화해 파싱했으며 JavaScript를 실행하지 않았다.

| 공식 Sheet 대조 | 내국인 | 장기외국인 | 단기외국인 |
|---|---:|---:|---:|
| 조회한 같은 날짜·시간·행정동 집계 | 1,000 | 1,000 | 1,000 |
| 모든 반환 성분의 총계가 공개여서 비교 가능한 집계 | 401 | 362 | 131 |

분모는 원천별 첫1,000집계이고 비교 시간은00~02시다. 같은 행정동이 시간에 따라 비교/제외 양쪽에 들어갈 수 있어 고유 행정동 수를 합산하지 않는다. 날짜·시각·행정동 식별 불일치와 원자료 대응 그룹 부재는0건이었다. 사전에 정한 오차 한도는 `(반환 성분 행 수+1)×0.01`이지만 실제 비교894건은 오차 한도 이내 수준이 아니라 **모두 정확히 일치**했다. 제외2,106건의 비공개 성분은 합산하거나 추정하지 않았다.

이 검사는 **격자 행을 행정동별로 합치는 처리**를 교차 확인한 것이다. 다른 행정동 행을 한 격자 총계로 만드는 모든 경우를 직접 승인한 것도, 독립적인 인구 실측이나 사람 비중복을 검증한 것도 아니다. 같은 기초 자료에서 만든 공식 게시 집계일 수 있다는 한계도 남는다.

OpenAPI 경로도 두 종류로 나눠 기록했다. 원천별로 완전 공개 후보3개를 지정한 추가 경로 필터는 비교0건·미일치/빈 응답3건씩이었다(`results.json`의official_reference). 별도로 날짜만 지정한 기본sample5행씩은 총15행이 같은 날짜·시간·행정동으로 대응했고 그중 장기외국인2건이 완전 공개여서 정확히 일치했다(`official-reference-default5.json`, `crosscheck.py`). 나머지13건은비공개성분으로제외했다. 기본sample은 Sheet 표본과 겹칠 수 있어894건에 더하지 않았다. 추가 경로 필터의 INFO-200 또는 미일치는 미제공/0명 근거로 쓰지 않았다.

당일 관측 쌍×24시간은 진단용 참조다. 하루 내내 한 번도 나타나지 않은 쌍은 포함하지 않고 공식 기대 모집단도 아니다. 총34,046개 부재 조합을 누락된 인구나 공급기관 오류 건수로 해석하지 않는다.

### 7.4 쟁점3: 현재 격자가2026-11-07 자료에 맞는가?

**판정: 관측 코드의 SHP 포함 검사와 현재 도형의 내부 정합 검사는 매칭 범위에서 통과했다. 공식 관측일별 적용·역사 버전·행정동 귀속은 확정 불가다.** 관측 전체100% 대응은 아니다.

- SHP10,125개 모두 코드에서 계산한5179 중심점·250m 사각형과 일치했다. 중심점 오차 한도는1mm이고 원본 사각형 꼭짓점 집합도 대조했다.
- 공식 격자 뷰어의10,125개와 ID 집합·중심점 속성은 모두 같았다. PROJ9.5.1로 변환한4326 위치와 뷰어 위치의 거리도 전부0.5m 이내였으며 최대0.134m였다. 이는 뷰어 좌표의 정밀도 차이를 허용한 검사다.
- DB10,125개 도형은 같은 PostGIS 변환의 NDR EWKB 전체 지문과 일치했다. 별도로 DB 도형을5179로 역변환한 bbox를 코드 산식 사각형의 bbox와 대조한10,125개도 모두1mm 이내였으며 최대오차는 약3.03×10^-9m였다. 변환 환경은 PostgreSQL17·PostGIS3.7.0·GEOS3.15.0·PostGIS PROJ9.9.0이다.

### 7.5 검사기의 검출력·재현과 최종 판단

검출기가 단순히 항상 통과하는지 확인하기 위해 메모리 안에서 알려진 결함을 주입했다. 실제 원본·DB는 수정하지 않았다.

- 완전키 행 하나 복제, 다른 행정동에 공개 프로필 복제, 고정 참조에서 행 하나 삭제를 각각 검출했다. 원본의 다른 프로필을 복제라고 오인하지 않는 음성 대조도 통과했다.
- 격자 중심점/도형을250m 이동한 입력을 공간 판정 함수가 거절했다. ZIP1바이트와 관측 원문 지문 변경은 해시 민감도 검사로 구분하며, 이것만으로 DB 비교기의 검출력을 주장하지 않는다.
- 별도 읽기 전용 세션에서 실제 `_verify_observations`와 `_verify_grid`의 양성/음성 대조를 실행했다. 원본은 모두 통과했고, 메모리의 관측값 하나를 바꾸고 기대 지문을 다시 계산한 입력은 `living_pop:stored_population_content`, geometry를250m 이동한 기대 입력은 `living_pop:stored_grid_content`로 거절됐다. DB 값·geometry는 변경하지 않았다.
- 공식 비교의 원래 합계 일치와 허용 한도를 넘도록 바꾼 합계의 불일치를 동일한 비교 helper로 원천별 확인했다. 주입값을 실제 관측이나 보고 수치로 사용하지 않았다.

원자료 전수·DB·복제 패턴·100회 기준선 실행은92.88초였고 Sheet 교차 검증과 추가 진단은 별도 실행이다. 비공개 증빙과 스크립트는 `%USERPROFILE%\SpotON-private-backups\population-empirical-20261114\`에 보관한다. `audit.py`는 원자료/DB/현재 뷰어 대조, `sheet_check.py --offline`은 보관한 공개 Sheet 응답의 교차 검증을 재현한다. 저장소 경로·기존 manifest와 원본 접근 권한이 필요하며 비밀 접속정보를 명령행에 넣지 않는다. 공개 보고서에는 건수·집합 지문·오차·판정만 남기고 관측값/좌표/코드/코드별 지문은 넣지 않는다.

이번 실증으로 **원자료를 보존한 행정동별 소계 처리와 현재 격자의 코드/도형 정합은 확인됐지만, 한 격자 안에서 행정동 간 값을 더할 수 있다는 가산성은 확정하지 못했다**고 판단한다. 검사는 원천별로 분리했으며 원천 간 개인 비중복도 이번 범위에서 확정하지 않는다. 그러나 개인 비중복, 모든 부재 행의 원인, 미매칭 예외와 공식 관측일별 적용 보증은 남아 있다. 현재 API가 요구하는 공간·모집단 완전성을 별도 설계 없이 선언할 수 없으므로 공개 인구 pending은 유지한다. 후속 구현에서는 이번 실증을 재사용하되 검증된 제공 범위와 제한을 응답 계약으로 명시해야 한다.
