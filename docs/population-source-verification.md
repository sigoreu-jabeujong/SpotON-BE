# 생활인구 원천 검증과 주야간 계산 준비

- 확인일: 2026-11-14 / 이슈 [#115](https://github.com/sigoreu-jabeujong/SpotON-BE/issues/115).
- 결론: **공식 근거 세 건이 미확정이므로 공개 인구 수치는 pending을 유지한다.** 독립적인 주야간 산술 계산 기반만 구현한다.
- 2026-11-14 사용자는 별도 공식 답변이 아직 없으며 문의 초안으로 진행하라고 답했다. 아래 문의는 제출 전 초안이고 실제 문의·회신 기록이 아니다.

전체 PDF를 새로 전수 검토하거나 원본 인구 ZIP을 재수집·재적재하지 않았다. 로컬 DB 조회는 metadata이며 전체 내용 hash 재검사·새 반경 조사·인구 합산은 수행하지 않았다. Render DB·설정·공개 API·FE는 변경하지 않는다.

공식 웹 조회에서 장기외국인 페이지는 첫 조회에 지연103을 반환했으나 다음 조회는 데이터 설명과 파일 목록을 정상 반환했다. 이 오류를 자료 미제공이나 인증 실패로 해석하지 않는다.

## 3. 확인된 사실과 남은 질문

### 3.1 시간과 표시 단위

활용 매뉴얼 PDF3쪽은 시간 코드00~23에 대응하는 각1시간 구간과 그 시간에 가장 오래 머문 격자에 인구를 배정하는 설명을 제공한다. 같은 사람의 서로 다른 시간 관측이 존재할 수 있으므로 24시간 합을 하루 고유 방문자 수로 표시하지 않는다. 공식 안내도 통신·공공데이터로 추계한 시간·공간 인구임을 설명한다. [공식 설명](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)

SpotON은 사용자 결정대로 주간06:00~18:00미만(06~17), 야간00~05와18~23으로 구분한다. 2026-11-14 [공식 홈페이지 상단 현황](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)의 주간09시~18시 산술평균·야간19시~08시 산술평균 안내와 구분해 **SpotON 기준**이라고 표시한다. 홈페이지의 경계를 임의로 미만 구간으로 다시 해석하지 않는다. SpotON은 같은 관측일의 두 구간이며 전날 밤부터 다음날 아침까지의 연속 체류를 분석하는 지표가 아니다.

### 3.2 다른 행정동 행의 합산: 미확정

정의서가 행정동을 key로 두고 활용 매뉴얼 PDF9/11쪽의 예제도 행정동을 보존한다는 점은 확인했다. 이는 `(date,hour,grid)`만으로 행을 중복 제거하면 안 된다는 근거다. 하지만 서로 다른 행정동의 값이 겹치지 않는 부분값인지, 모든 필요한 행정동 구성요소가 파일에 있는지는 이 확인 범위에서 입증하지 못했다.

시각별1인1격자라는 추계 원칙은 제공 CSV의 모든 행정동 행이 빠짐없이 중복 없이 구성됐다는 증거와 다르다. 공급기관의 합산 규칙과 기대 구성 근거가 있어야 원천 행을 격자별 시간 총계로 만들 수 있다.

### 3.3 없는 행과 비공개: 의미를 구분

공식 원천은 소규모 값을 `*`로 비공개 처리한다고 안내한다. 2026-11-14 홈페이지 유의사항의3명 미만과 개별 데이터 설명의3명 이하처럼 임계값 표현 차이도 있으므로 숫자에서 마스킹 여부를 추측하지 않고 원문 마커를 보존한다. [공식 유의사항](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do), [내국인 원천 설명](https://data.seoul.go.kr/dataList/OA-22784/S/1/datasetView.do)

활용 매뉴얼 PDF9쪽의 예제에는 비공개 값을 특정 숫자로 대체하는 코드가 있지만, SpotON은 사용자 결정대로 이를 적용하지 않는다. 원본 숫자0만 observed/0, `*`는 suppressed/null, 실제 빈 셀은 missing/null, 행 부재는 no_data로 구분한다. 이것은 [#53 적재](designs/feat53-living-population-import.md)·[#90 정책/로그](designs/feat90-population-quality-logs.md)의 기존 처리 정책이며, 행이 없어진 공급기관의 사유가 확인됐다는 뜻이 아니다.

격자에 숫자 행이 있더라도 다른 행정동 구성요소가 누락됐는지는 별도 문제다. 알려진 숫자만 SQL SUM으로 더해 완전한 시간 총계라고 표시하지 않는다.

### 3.4 현재 SHP와2026-11-07 관측의 대응: 미확정

활용 매뉴얼 PDF5쪽은 국가표준격자 코드와 좌하단/중심점 좌표의 관계를 설명한다. 이 정의와 현재 SHP/DB hash 일치는 좌표 체계와 사용 파일을 식별하는 근거다. 해당 SHP의 날짜별 제공 범위·수정 이력·특정 관측일의 모든 코드 대응까지 확정하지는 않는다.

기존 #53 검증에서 관측의 격자1개·비공개24행이 SHP에 매칭되지 않았다. 이번 metadata 조회에서 그 원본 관측을 새로 전수 대조한 것은 아니다. 가짜 좌표를 만들지 않고 기존 unlocated 보존·공간 집계 제외 정책을 유지한다. 공급기관의 관측일별 격자 적용 범위와 예외 처리가 필요하다. [기존 적재 근거](designs/feat53-living-population-import.md)

## 4. 내부 계산 계약

[계산 모듈](../app/analysis/day_night.py)은 이미 동일 관측일·공간·모집단으로 검증한 시간별 총계24개를 향후 입력받기 위한 산술 기반이다. 현재 서비스에서는 호출하지 않는다. 이 함수가 원천 행의 합산·행정동 구성·관측일·격자 적용을 검증하는 것은 아니다.

입력은00~23 순서의 Decimal/None tuple24개이며 숫자는0이상·1e15미만·표현상 소수5자리 이하다. 이 범위는 현재 내부 입력 계약이고 향후 실제 총계 타입은 별도 검토한다. None은 상위에서 해당 시간 총계를 제공할 수 없다는 표시이며 원래 결측·비공개·행 부재의 원인과 provenance는 상위가 보존한다. 상위는 비공개·셀 결측·행 부재를0으로 바꾸지 않고 None으로 전달해야 한다.

```text
D = P[6] + ... + P[17]
N = P[0] + ... + P[5] + P[18] + ... + P[23]
주간 비중 = D * 100 / (D + N)
야간 비중 = 100 - 표시한 주간 비중
주간/야간 평균 = D / 12, N / 12
주야간 배수 = D / N
```

비중만 최종 소수1자리 HALF_UP으로 표시한다. 평균과 배수는50자리 Decimal 문맥의 결과이며 최종 표시 반올림은 소비자가 정한다. D/N과 비중(%)은 서로 다른 값이다. D·N은 시간별 추정치를 누적한 값이고 인원이나 일일 고유 방문자 수로 표시하지 않는다. 표시0.0%만으로 실제 인구0을 판정하지 않는다.

| 입력 | 내부 상태 | 합계·평균 | 비중 | 배수 |
|---|---|---|---|---|
| 정상24시간, D+N>0,N>0 | calculated | 산술 결과 | 계산 | 계산 |
| 정상24시간, D>0,N=0 | calculated | 산술 결과 | 100%/0% | null |
| 정상24시간, D=N=0 | zero_total | 입력 합계0, 상위가 관측0을 전달했다는 전제 | null | null |
| None이 하나 이상 | incomplete | 전부 null | null | null |
| 잘못된 길이/타입/값 | 고정 ValueError | 결과 없음 | 결과 없음 | 결과 없음 |

calculated는 산술 성공만 뜻한다. 공개 API의 fact/verified와 연결하지 않는다. 모든 입력을 검사한 뒤 None을 판정하며, 잘못된 값이 있으면 incomplete로 숨기지 않는다. 원본 값·식별정보를 오류나 repr에 넣지 않는다. 새 Context로 전역 Decimal의 precision/rounding/traps/Emax/Emin/clamp와 분리한다.

## 5. 제공기관 문의 초안 — 미제출

제출 경로는 [서울시 생활인구 안내의 문의하기](https://data.seoul.go.kr/dataVisual/seoul/seoulLivingPopulation.do)를 사용한다. 실제 제출·기관 회신·적용 승인으로 표시하지 않는다.

**제목: 서울 생활인구250m의 행정동별 행 합산·미제공 행·격자 적용 범위 확인 요청**

서울 생활인구 내국인(OA-22784), 장기외국인(OA-22785), 단기외국인(OA-22786)의2026-11-07 일별 자료를 이용하려고 합니다. 현재 안내 페이지의 정의서·추계 매뉴얼·활용 매뉴얼·250m EPSG5179 SHP를 함께 확인했습니다. 아래 세 항목의 공식 처리 기준과 근거 문서 또는 버전을 부탁드립니다.

1. 동일 원천·일자·시각·CELL_ID에 서로 다른 H_DNG_CD 행이 여러 개 있을 때, SPOP은 서로 겹치지 않는 부분값인가요? 해당 행들을 모두 합산하면 그 격자의 시간별 생활인구 총계가 되나요? 기대하는 행정동 구성과 누락 여부를 확인할 공식 매핑이나 규칙이 있나요?
2. 특정 원천·시각·격자·행정동 조합의 행이 CSV에 없을 때,0명·비공개 생략·측정/추계 불가·비대상 중 어떤 의미인가요? 행이 제공되는 조건과 누락 검증 기준, 숫자 행만으로 구성 완전성을 확인할 수 있는지 안내 부탁드립니다.
3. 현재 안내 페이지의250m EPSG5179 SHP(infId=DOWNLOAD,infSeq=4,seq=37)가2026-11-07 관측의 공간 대응 파일이 맞나요? 적용 기간·버전 이력과 원천 격자가 SHP에 없는 경우의 공식 처리 방법 또는 보완 파일을 부탁드립니다. 현재 사용 ZIP SHA256은 `5f7f95db30f1d4a433d9905b281c3fb95b59cd8200985512a897326208bf525e`입니다.

비공개 값이나 원본 관측값을 문의에 첨부할 필요는 없으며, 격자 예외 사례의 식별 정보가 필요하면 기관이 안내한 전달 경로와 범위를 먼저 확인합니다.

## 6. 공개 연결을 재개할 조건

1. 세 항목의 공식 근거와 관측일별 적용 범위를 확보해 검증 기록으로 남긴다. 사용자 선택 정책이나 파일 hash 일치만으로 이를 대체하지 않는다.
2. 동일 반경의 격자·원천·행정동 구성과 시간별 완전성을 검증한다. 비공개·셀 결측·행 부재·미좌표를 보존하고 실제0과 구분한다.
3. 인허가 적용일과 별도로 인구 관측일을 반환하고, 미래 관측·서로 다른 날짜/모집단의 혼합을 막는 버전 선택을 구현한다. 이번에는 자동 날짜 선택을 구현하지 않았다.
4. activity/Risk의 typed 인구 응답·AI 범위·캐시/출처·FE 표시 계약을 함께 설계하고 실제 반경·날짜·상태 검사를 거쳐 연결한다. 이때까지 현재 인구 pending을 유지한다.

이번 구현·검토·검사 결과는 [#115 설계](designs/feat115-population-time-basis.md)에 기록한다. #115는 공식 근거와 공개 연결 후속 추적용으로 열어 둔다.
