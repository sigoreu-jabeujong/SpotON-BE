# 해석 본문과 유의점의 역할 변경

사용자 요청으로 유의점은 이점의 반대인 불리한 신호로 정의한다. 자료 한계·현장 확인·일반 면책으로 채우지 않는다. 비교 가능한 폐업률이 서울보다 높거나 생존율이 서울보다 낮은 경우, 동일 기간 폐업 기록이 개업보다 많은 경우를 명시적인 adverse_signals로 모델에 전달한다. 기간/단위/상태/결측을 확인하며 주의 항목은 불리한 비교의 두 근거를 함께 인용해야 한다. 비교가 없거나 유리/동률/결측이면 빈 유의점을 허용한다. 점포 수·매출의 임의 높고 낮음 기준이나 주소 이력의 폐업 건수만으로 단점을 만들지 않는다.

수치 해석은 대표 수치/비교 → 조건부 특성 → 운영상 시사점의 문단이다. 예를 들어 야간 생활인구가 주간보다 많으면 야간 체류·주거 수요와 연결된 생활권 가능성과 저녁 서비스/영업시간 검토를 설명할 수 있다. 생활인구만으로 유흥/먹자 상권·실제 소비/방문 활발·창업 성공을 확정하지 않는다. 확률 근거 없는 '가능성이 높다' 대신 가능성/시사라는 조건부 표현을 사용한다.

서버는 해석의 의미 제약을 계속 지키되, 개별 점포 매출/수익 아님·실제 고객 수 아님·범위/시점 차이·현장 확인 등 반복 문구를 본문에 덧붙이지 않도록 지시한다. 필수 limitations는 응답에 보존하며 FE가 수치로 본 해석 제목 옆 기존 InfoPopover에서 클릭할 때 표시한다. 유의점 카드와 하단의 반복 한계는 제거하고, 팝오버에는 고정 한계/기존 notice/시간대와 평균 영업기간 및 현장 확인 해설을 포함한다. 계약 전 체크리스트3개는 유지한다. PDF에는 클릭형 팝오버를 인쇄하지 않는다.

모델/추론/키·DB·3호출/재시도0·수치/단위/근거 검사와 시간 예산은 변경하지 않는다. 생성 버전v2.2와 FE 캐시prefix v3로 기존 반복 경고 결과와 구분한다. 실제 공공 지표의 별도 Sol3역할 호출은6.16/2.34/10.05초에200이며, 이점3·유의점0(불리한 비교 없음)·요약6문단이 근거 검증을 통과했다. 야간 체류·주거 수요의 가능성과 저녁 서비스/영업시간 시사점이 작성됐고 '실제 고객이 아니므로 확인'이라는 반복으로 끝나지 않았다.

회귀83건과 BE ruff/mypy130파일, FE 카드/숨김 상태 회귀·lint/production v2 빌드를 확인했다. 최종 운영 생성·팝오버 클릭/닫힘·모바일/인쇄 확인은 배포 PR에 기록한다.
