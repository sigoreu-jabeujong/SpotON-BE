# BE 개발 전 보완 및 API 계약 동기화

이 문서는 BE 계획서 점검에 따라 채택한 개발 방향과 외부 명세 반영 대상을 기록한다. 저장소에는 API 명세서 v1.2·데이터 활용 명세서·기능 명세서 원본이 없으므로 아래 사항을 해당 원본에 반영 완료했다고 간주하지 않는다. 현재 작업은 BE 문서 보완이며 FE는 수정하지 않는다.

## 적용 기준

- 기본 브랜치는 `main`, 개발 통합 브랜치는 `develop`이다. 최신 `develop`에서 작업별 새 브랜치를 만들고 PR로 통합한다.
- FE·BE 별도 저장소를 유지한다. PDF 참고 자료와 충돌하면 사용자 결정과 기존 BE 문서가 우선한다. 추가 실무 규칙은 [be-development-rules.md](be-development-rules.md)에서 관리한다.
- 지원 범위는 서울의 카페와 한식·중식·일식·양식이다. 분식·기타 음식점 등을 제외한 것은 의도된 범위 축소다. LQ는 구현하지 않는다.
- 수치 제공 데이터셋은 출처·사용 조건·공간 단위·갱신 주기를 검증한 후 활성화한다. 특정 데이터 최신 분기나 누락률·표본 수를 원자료 확인 없이 확정하지 않는다.
- 원본 좌표와 날짜·업태, 정제 사유를 보존하고 검증되지 않은 값을 분석에 포함하지 않는다.

## API·기능·데이터 명세 반영 대기

| 대상 | 반영할 내용 | 구현 전 확인 |
|---|---|---|
| 공식 폐업률 | 현재는 최신 공표·적재 검증 분기, 과거는 해당 분기. 요청 기준일과 실제 적용 분기를 구분 | 분기 메타데이터 필드명, 공표·배치 이력, 결측 상태 |
| 상권변화지표 | 원자료 그대로 제공하는 `market_change`를 공식 영역으로 이동 | 해당 데이터셋 분기, 공간 단위, 원천 유형 enum |
| 공식 창업위험도 | 외부 링크 전용, 수치 생성 금지 | `link_only` enum, 공식 URL 유효성, 복사 안내 필드 |
| 상권 판정 | 세부 상권 우선·관광특구 병기·상권 밖 수치 미제공 및 반경 내 상권 목록 | 경계 판정, 중첩 후보, 사유·목록 필드 |
| 데이터 상태 | 미확보 `pending`, 조건별 결측 `no_data` 구분 | 지표별 상태 enum 및 FE 표시 |
| 이력 | 지원 업종 전체의 자리 이력, category는 진단 맥락으로 유지 | 기존 category 필터 의미와 충돌 여부, FE 이력 표시 |
| 범위 | 분식·기타 음식점 등 제외, LQ 제외 | 기능 F-04·지표 M-05 및 서비스 개요·데이터 활용 명세 동기화 |
| 좌표·정제 | 원본 좌표, 플래그, 보완 이력 및 날짜별 제외 사유 | 원천 CRS, 원본 보관 정책, 플래그 enum |
| AI 제한 | 공급자 429는 기존 `AI_UNAVAILABLE` 사용 | 재시도 안내·HTTP 상태·시간 예산을 API 명세에 명시 |

새 필드·enum과 이력 category 의미 변경은 원본 API 명세와 대조하고 FE와 동기화한 후 구현·배포한다. 외부 문서를 찾을 때 이 표를 반영 체크리스트로 사용한다.

## 공식 창업위험도 응답 보완안

다음은 지표 객체 예시이며 최상위 응답은 기존 `{data, meta, error}`를 유지한다. URL은 사용자 점검안의 후보로, 외부 연계 시 유효성을 확인한다.

```json
{
  "id": "official_risk",
  "type": "official",
  "value": null,
  "status": "link_only",
  "link": "https://golmok.seoul.go.kr/stateDistrict.do",
  "copy_text": "상권명 · 업종명"
}
```

`copy_text`에는 판정된 상권명·업종명을 사용하고 사용자 주소·좌표를 포함하지 않는다. 상권 밖이거나 판정이 불명확하면 상권명을 만들어내지 않는다. 링크 안내를 공식 수치 확보 완료로 계산하지 않는다.

## 보수적으로 채택한 처리 방향

- 기타 업태의 카페 키워드 후보는 검토 전 집계에서 제외한다. 이름만으로 업종을 확정하지 않는다.
- 한시적 사업장은 원본을 보존하고 구분하되 기본 장기 입지 분석 집계에서 제외한다.
- 이력은 지원 업종 전체를 보여주는 방향으로 보완한다. 제외 업종까지 포함하는 전 업종 이력은 추가하지 않는다.
- 추정매출·생활인구·상권변화지표·주야간 인구비는 조건부 범위로 두고, 미확보 동안은 `pending` 계약과 안내를 검증한다.
- 제외 업종 안내에는 지원 범위 한정 집계임을 명시한다. 원자료를 확인하지 않은 비율·건수는 안내 문구에 사용하지 않는다.

## AI 운영 기준과 확인 출처

기본 모델은 `gemini-3.5-flash-lite`로 설정하되 모델 선택은 환경변수로 유지한다. 모델 존재와 프로젝트의 무료 호출 가능 여부는 별개이므로 실제 AI 연계 시 둘 다 확인한다.

- [공식 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)
- [공식 호출 한도](https://ai.google.dev/gemini-api/docs/rate-limits)
- [공식 모델 종료 일정](https://ai.google.dev/gemini-api/docs/deprecations)
- [공식 요금·무료 범위](https://ai.google.dev/gemini-api/docs/pricing)

분당 15회를 모든 모델·계정에 적용하지 않는다. 프로젝트별 요청·토큰·일일 한도를 확인하고 설정으로 관리한다. 종료 일정과 자동 전환도 모델별 확인 대상으로 두며 2.5 계열 전체의 일괄 전환 날짜를 확정하지 않는다. 한도 초과에는 제한된 백오프를 적용하고 실패 시 지표 결과를 유지한 채 AI만 이용 불가로 처리한다.
