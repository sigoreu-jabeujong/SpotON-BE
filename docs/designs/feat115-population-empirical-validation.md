## 4. Claude 설계 검토

Codex 실행 전 결정: 실제 데이터 중복 검사는 H_replicate(다른 admin에 전체 프로필 복제)와 H_split(서로 다른 부분값) 중 단순 전체복제 가설의 반례를 찾는다. 집계 자료로 사람 중복0을 확정하지 않는다. 총계가 공개 양수이고 상세에 숫자가2개 이상인 행의 정규화 프로필을 비교하며 marker는 marker대로 비교하고 전부 비공개/숫자0 프로필은 증거로 쓰지 않는다. 같은 source/hour/admin 쌍의 다른 격자끼리 비교하는 고정 seed11520261114·100회 회전 기준선을 함께 계산한다. 프로필차이는 부분 인물 중복을 배제하지 않는다.

### 4.1 근본 한계 (보고서에 그대로 명시)

- 집계 원자료에는 개인 식별자가 없으므로 어떤 집계 검사도 "개인 비중복"을 증명할 수 없다. 완전키 중복 0건은 파일 무결성 결과일 뿐이며 사람 중복 판정과 다른 항목으로 보고한다.
- 시간대별 값은 시점 재고(stock)이므로 같은 사람이 여러 시간·여러 날에 반복 집계되는 것은 설계상 정상이다. 24시간 합·일일 합을 "인원 수"로 부르지 않는다는 문장을 결과에 포함한다.
- 내국인/장기/단기 외국인은 모집단 정의가 달라 원천 간 합산·비교를 중복 검사 근거로 쓰지 않는다(원천 간 동일 인물 가능성은 확정 불가로 별도 기재).
- 공간 검사는 격자 도형과 코드의 정합만 보여줄 수 있다. 격자↔행정동 귀속의 정확성(2026-11-07 행정동 경계 버전)은 행정동 경계 원자료 없이 판단 불가이며, 그 원자료가 범위 밖이면 "확정 불가"로 남긴다.

### 4.2 중복 검사 설계 우려와 보완

1. **대립 가설의 예측을 먼저 고정.** H_split(격자 값이 행정동 조각으로 분할됨)과 H_replicate(격자 전체 값이 각 행정동 행에 복제됨)가 각각 무엇을 예측하는지 실행 전에 적는다. 예: 2개 이상 admin에 걸친 (source, grid)에서 24시간×전 컬럼 프로필 완전 일치 비율이 H_replicate면 거의 전부, H_split면 소수일 것으로 예측. 이 비율 자체가 사람 비중복을 증명하지는 않지만 두 가설을 구분하는 정보가 된다.
2. **우연 일치 귀무모형.** 작은 값·반올림·비공개(`*` 등) 셀이 많으면 H_split에서도 프로필이 우연히 같을 수 있다. (a) 전 셀 비공개/0 행은 증거에서 제외하고 그 건수를 따로 보고, (b) 같은 admin 집합 안에서 격자 라벨을 무작위 재배치한 순열 기준선(또는 같은 크기·같은 값 분포의 서로 다른 격자 쌍 비교)으로 기대 우연 일치율을 계산해 관측치와 나란히 둔다. 시드와 반복 횟수를 기록한다.
3. **동등성 정의 명시.** 비교 컬럼 목록, 수치 정규화(소수 자릿수·반올림 규칙), 비공개 셀끼리 일치로 볼지 여부를 사전 정의한다. 부분 일치(총계만 같고 상세 다름)는 별도 범주로 센다.
4. **공식 행정동 집계 대조는 필요조건 검사로만.** 같은 날짜·같은 원천의 공식 행정동 값이 있을 때 Σ(admin,grid) 행 ≈ 공식 admin 값이면 "행정동 수준 이중계상과 불일치하지 않음"까지만 말한다. 허용오차는 반올림·비공개 규칙에서 유도해 실행 전에 고정하고, 비공개 셀이 포함된 admin은 비교에서 빼서 표본 범위(포함/제외 admin 수)를 남긴다. 체계적으로 Σ > 공식값이면 반례로 기록한다. 같은 날짜 자료가 없으면 대조 생략 + 확정 불가이며, 다른 월자료로 대체하지 않는다(설계 2절과 일치, 유지).

### 4.3 행 부재 검사 설계 우려와 보완

1. **참조 모집단의 순환성.** "그날 한 번이라도 관측된 (source, admin, grid)×24"는 하루 종일 행이 없던 쌍을 원천적으로 볼 수 없다. 이 한계를 결과 표 바로 옆에 적고, 가능하면 독립 분모를 하나 더 둔다: SHP 격자 전체 대비 원천별 관측 격자 비율(admin 차원 없이). 둘을 섞지 않는다.
2. **상태 분류 고정.** 셀 단위로 {행 없음, 행 있으나 빈칸, 비공개 표기, 문자 그대로 0, 양수}를 상호배타로 세고 원천·시간대별 분할표로 보고한다. 문자 0이 전혀 없고 행 없음이 많다면 "0→행 생략 정책과 정합"이라는 실증 추정까지만 쓰고 원인은 확정 불가로 둔다.
3. **원인 구분을 위한 비채움 검사.** 부재 셀의 같은 (source, admin, grid) 인접 시간대 값 분포(비공개/소값 비율)를 관측 셀의 그것과 비교하는 것은 허용되나, 결과는 분포 비교로만 쓰고 부재 셀에 값을 추정·보간하지 않는다.
4. **단일 날짜 한계.** 하루 자료만으로는 날짜 특이적 결측과 상시 정책을 구분할 수 없음을 명시한다.

### 4.4 공간·hash 검사 설계 우려와 보완

1. **코드 산식 검사의 의미.** 코드→5179 중심점/250m 사각형 일치는 SHP와 명명 규칙의 내부 정합 검사다. 격자 체계 자체는 고정 격자이므로 "2026-11-07 적용성"의 실질 쟁점은 (a) 원천 격자 코드의 SHP 포함 여부, (b) 행정동 귀속 정확성이다. 결과를 이 두 축으로 나눠 보고한다.
2. **미매칭 분류.** 미매칭 격자를 {코드 문법 오류, 문법은 맞으나 격자 범위 밖, 범위 안이나 SHP에 없음}으로 나누고, 행 수 비율과 함께 비공개 아닌 값의 합 비율(절대 총계 아닌 비율만)도 원천별로 보고한다. 도형 생성은 하지 않는다(유지).
3. **.prj/좌표계 확인.** SHP가 이미 5179인지, 변환이 필요한지 .prj로 확인하고 PROJ/GEOS/PostGIS 버전을 기록한다. 변환이 필요한 경우 좌표 비교 허용오차(예: mm 단위)를 사전 고정한다.
4. **hash 대조의 독립성.** "동일 PostGIS 변환 지문"을 DB 적재와 같은 코드 경로로 재계산하면 동어반복이다. 최소 하나는 독립 경로(예: 순수 산술로 만든 사각형 꼭짓점 vs DB geometry)로 계산하고, 정규화 규약(키 정렬 순서, 좌표 반올림 자릿수, ring 방향·시작점, WKB 엔디언/차원)을 문서화한다. 일치/불일치 건수와 대조 대상 행 수를 함께 적는다.
5. **행 수 대사.** 원천별 원문 줄 수 − 헤더 = 파싱 성공 + 거부 + (빈 줄)을 검증하고 합이 531,922와 맞는지 확인한다. 불일치 시 다른 판정 전에 중단한다.

### 4.5 테스트를 유익하게 만들되 값을 만들어내지 않는 방법

- **양성 대조(mutation) 검사.** 각 검사기가 실제로 반례를 잡는지, 메모리 안의 원자료 복사본에 알려진 결함(행 하나 복제, 한 격자 프로필을 다른 admin에 복제, 행 하나 삭제, 도형 1칸 이동, hash 입력 1바이트 변경)을 주입해 검출되는지 확인한다. 주입본은 저장·DB 적재·보고 수치로 쓰지 않고 "검출됨/미검출" boolean만 남긴다. 실제 결과는 이 검출력이 확인된 검사기로만 판정한다.
- **음성 대조.** 결함 없는 원본에서 검사기가 거짓 양성을 내지 않는지 함께 기록한다.
- **사전 등록.** 4.2~4.4의 판정 규칙·허용오차·제외 기준을 실행 전에 비공개 증빙 디렉터리에 시각과 함께 남기고, 사후 변경 시 변경 사유를 보고서에 적는다.
- **분모 항상 병기.** 모든 비율은 분자/분모/제외 건수를 같이 쓴다.

### 4.6 공개 안전 우려

- 격자 코드(약 1만 개)·admin 코드·작은 정수 값은 엔트로피가 낮아 개별 hash를 공개하면 사전 대입으로 복원된다. 공개 보고서에는 집합 전체 지문 1개(또는 건수)만 두고 코드별·행별 hash는 비공개 증빙에만 둔다.
- 소수 셀 건수 분할표가 특정 격자·시간을 지목할 정도로 세분되지 않게 원천×시간대 이상으로 집계한다.

### 4.7 수용 조건 (모두 충족 시 결과 문서 반영)

1. 항목마다 "검사 통과 / 반례 / 실증 추정 / 확정 불가" 중 하나와 근거 검사, 분모, 범위를 적는다. 사람 비중복은 어떤 결과든 "확정 불가(집계 자료 한계)"로 둔다.
2. 행 수 대사와 원본 SHA256 검증이 통과한 뒤에만 나머지 판정을 기록한다.
3. 모든 검사기에 양성·음성 대조 결과가 붙어 있다.
4. 중복 패턴 결과에 우연 일치 기준선이, 공식 대조에 사전 고정 허용오차와 제외 admin 수가 붙어 있다. 같은 날짜 공식 자료가 없으면 대조를 생략했다고 적는다.
5. 행 부재 결과에 참조 모집단 정의와 순환성 한계가 붙어 있고 어떤 값도 채우지 않았다.
6. 공간 결과가 "격자 코드 포함" 과 "행정동 귀속" 두 축으로 분리되어 있고, hash 대조에 독립 경로·정규화 규약·환경 버전이 기록되어 있다.
7. 공개 문서·로그·커밋에 원문 행·총계·좌표·코드·코드별 hash가 없음을 diff 검사로 확인했다.
8. API pending 해제·DB provenance 변경·production 기능 추가가 없고 #115가 열려 있다.

## 6. Claude 결과 검토 (2026-11-14)
