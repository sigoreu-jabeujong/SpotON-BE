### 6.3 링크가 실제 연결되는 곳

- 8센터의 url은 모두 같은 MSS 게시판 **공고 상세 페이지**(`View.do?bcIdx=1071565&cbIdx=310&parentSeq=1071565`)다. 센터 페이지·연락처 페이지·신청 페이지가 아니다. 사용자는 공고 첨부 PDF를 내려받아 25쪽 별표2를 찾아야 하며, 전화번호는 응답 description 안에만 있다. §2의 "개별 지점/예약/자동 신청 URL로 표현하지 않는다"와 "첨부 25쪽 표 확인 안내"는 반드시 지킨다.
- 한 응답에는 관할 1개+공통4개가 들어가므로 같은 응답 안에서 URL이 겹치지 않는다. 8개 항목의 URL이 같은 것은 카탈로그 내부에서만 생긴다. "URL 중복 제거 금지"는 카탈로그/테스트 수준의 규칙이며 응답 동작에는 영향이 없다.
- 게시판 공고는 삭제·이동될 수 있다. 실제 HTTP 확인을 했다면 날짜와 함께 §7에 따로 기록한다. 이번 검토에서는 접속 여부를 확인하지 않았다.

### 6.4 URL 정확 문자열 정책 (**B1**)

현재 `SupportLink.official_https_url`은 `?`·`#`가 있으면 무조건 거절하고, 호스트가 `OFFICIAL_HOSTS` 4개일 때만 허용한다. 새 공고 URL에는 `?`와 `&` 쿼리가 있으므로 지금 검증기를 그대로 두면 카탈로그 생성 단계에서 실패한다. §3의 "새 공고 URL 정확한 문자열1개만 별도 허용"과 "query 거절"은 함께 지켜야 하므로 다음처럼 명시한다.

1. 순수 상수 모듈의 `MSS_NOTICE_URL`과 **바이트 단위로 완전히 같을 때만**(`value == MSS_NOTICE_URL`) 곧바로 허용한다. 정규화·디코딩·대소문자 무시·파라미터 정렬 후 비교는 하지 않는다.
2. 그 외 값은 기존 경로(제어문자/`?`/`#` 거절 → https·ASCII netloc·4호스트)를 그대로 거친다. `www.mss.go.kr`를 `OFFICIAL_HOSTS`에 **추가하지 않는다**. 추가하면 해당 호스트의 쿼리 없는 모든 경로가 허용된다.
3. 상수 값 자체에 대한 계약 테스트: https·netloc `www.mss.go.kr`·포트/userinfo/fragment 없음·쿼리 키가 정확히 `bcIdx,cbIdx,parentSeq`이고 값이 정확히 `1071565,310,1071565`.

### 6.5 4개→5개 호환성 평가

- 구 생략(category만 있는 경우 포함): 목록 4개·순서·항목 바이트가 기존과 같아야 한다. 바뀌는 것은 `link_catalog_version`뿐이다. §2에 "v2는 구 생략 응답에도 적용"이라고 한 줄 명시한다(카탈로그 전체 버전이므로 v2 적용이 맞다). `prioritization`은 기존 `{status, reason}` 2키를 그대로 두고 생략 응답에 `category_applied`를 추가하지 않기를 권한다(v1 소비자 영향 최소화).
- 구 지정: 4개 → 5개이고 첫 항목이 새 관할 항목이 된다. 현재 FE가 sigungu를 보내지 않으면 영향이 없다. sigungu를 보내면서 4개 고정·인덱스 접근·`slice(0,4)`·`seoulsbdc`가 첫 항목이라는 가정이 있으면 화면이 바뀐다. FE 요청서는 (a) 배열 길이 가정 금지, (b) 순서 보존, (c) `meta.district_contact_source`·`prioritization.category_applied`는 구 지정일 때만 있는 선택 필드, (d) `status: applied | not_applied` 판별 union을 명시한다. FE 실제 코드는 이번 검토 범위가 아니어서 확인하지 않았다.
- `applied`의 의미: **구 관할 연락처 1개를 앞에 둔 배열 순서**만 뜻한다. 현재 신청 가능 여부·지원 자격·자금 한도·모집 여부·업종(category) 추천·맞춤 선정을 뜻하지 않는다. `category_applied:false`는 유지하고, category 값이 응답 목록/순서에 어떤 영향도 주지 않음을 테스트로 고정한다. title/description에 "추천", "맞춤", "신청 가능", "대상", "자격 충족" 같은 판정성 문구를 쓰지 않는다. BE CLAUDE.md #70 절의 "지역/업종별 우선 정렬 미적용·네 곳 전체·고정 순서"는 "구 지정 시 관할 연락처 우선, 업종 정렬은 미적용"으로 갱신해야 한다(§4 문서 갱신 범위에 포함됨).

### 6.6 기존 코드·테스트 영향 (**B2**)

- `routers/support.py`는 현재 `query`를 받고도 버린다. `get_support_links(query)`로 전달하고 서비스는 `query: SupportLinksQuery | None = None`로 인자 생략 호환을 유지한다.
- 다음 기존 테스트는 의도적으로 **바뀌어야 한다**. 실패를 수정하지 않고 그대로 두거나 단언을 약화하지 않는다.
  - `test_all_valid_district_category_combinations_preserve_all_links`: 모든 구를 baseline과 같다고 단언한다 → 구 생략/지정으로 나눠 다시 작성.
  - `test_general_catalog_contract_and_no_runtime_io`: `support-links-v1` 단언 → v2.
  - `test_internal_errors_are_safe_and_no_store`: monkeypatch한 `broken()`이 인자를 받지 않는다 → 라우터가 query를 넘기면 `TypeError`가 나도 500이 되어 우연히 통과할 수 있다. `broken(*_args)`로 바꿔 의도한 실패 경로를 검사한다.
  - `test_catalog_and_response_mutation_are_isolated`: 인자 생략 `len==4`는 유지하고, 구 지정 응답의 변조 격리를 추가한다.
- `SUPPORT_LINKS`(공통4)와 관할 8개를 별도 tuple로 두어 기존 import·fallback이 바뀌지 않게 한다. 관할 매핑은 `MappingProxyType` 또는 frozenset 기반 불변 구조로 둔다.
