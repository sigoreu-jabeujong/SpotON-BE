# AI 상권 해석 문단 개편 (#130)

2026-11-14 사용자 요청에 따라 FE와 BE를 함께 수정한다. 기존의 FE 직접 수정 금지·데스크톱 전용 기준은 이번 AI 개편 범위에서 최신 요청으로 대체한다. 운영 배포와 원천 데이터 보정은 별도 작업이다.

## 구현 결정

현재 API는 같은 읽기 전용 트랜잭션에서 Risk·활동·선택 건물 이력을 다시 조회한다. 이 경로와 숫자·출처 검증을 재사용한다. 자유 생성 문장을 숫자 목록과만 대조하면 수치의 주체·분모·미래 사건을 잘못 연결한 문장까지 통과할 수 있어, **서버가 실제 자료로 문단 후보를 만들고 모델이 네 흐름에서 문단 ID를 하나씩 선택**하도록 확장한다. 고정 예시 응답이나 모델 장애 시 대체 해석은 사용하지 않는다. `method=server_sentences_model_ordering`을 유지해 생성 방식을 사실대로 표현한다.

응답에 `body`, `paragraphs[{text,indicator_ids}]`, `used_indicator_ids`, `evidence`를 추가한다. 기존 배열은 이전 클라이언트와 내부 근거 보존을 위해 유지한다. 본문은 현황→서울 비교→활동/YTD→실제 준비와 참고 안내 순서다. 건물 총건수·위치 분할·최신 상태의 이후 폐업 수는 본문에서 제외한다. 서로 다른 업종/위치의 이력 집계만으로 의미 있는 과거 흐름을 확정할 수 없어 건물 이력은 내부 근거와 한계 안내로 보존한다.

AI에는 주소·좌표·점포명·관리번호·건물 키·층호·내부 UUID를 보내지 않는다. 선택 주소는 FE 조건 요약에 표시하며, 서버는 요청 좌표와 필터로 데이터를 계산한다. 점포별 업종·개폐업일·최신 상태·면적·거리는 기존 활동 조회의 행을 사용해 집계하고, 식별정보 없는 현황/거리/면적/이후 상태 분할만 문맥에 투영한다. SQL 조회 횟수는 추가하지 않는다.

모델은 승인된 후보 ID만 반환할 수 있다. 없는 수치/공식 등급/매출·수요 예측 문장을 삽입하거나 문단 흐름을 바꾼 선택은 거절한다. 선택 형식·숫자·금지 표현·개인정보·현재 후보 유효성 검사를 유지하고, 실패 시 최대 한 번 재생성한다. 프롬프트는 v8, 선택 캐시 규칙은 v4로 올려 이전 결과를 무효화한다. 프로세스 한도5회/분·50회/일·동시2와 전체20초 예산, no-store를 유지한다.

## 집계 정의 확인

| 항목 | 코드에서 확인한 기준 |
|---|---|
| 최근 12개월 | 기준일 T와 같은 전년 월·일 L의 `(L,T]`. 존재하지 않는 날짜는 월말로 제한. 표시는 L 다음 날부터 T까지 포함 |
| 참고 폐업률 | 최근 구간 폐업 기록 / (T 시점 영업 기록 + 최근 구간 폐업 기록), 최소 분모10 |
| 생존율 | 서로 다른 진입연도의 개업 1·3주년 관측 집단, 최소 분모5. 주년 이후 폐업도 포함 가능 |
| 서울 비교 | 같은 업종·T·면적·가맹·두 unknown 필터와 좌표 확보 조건, 반경만 서울 전체로 확장. 공식 서울 통계가 아님 |
| 차이 | 표시된 소수 첫째 자리 지역/서울 비율을 Decimal로 빼 %p로 표현. 분모와 기간은 evidence에 유지 |
| 평균 경과 기간 | T에 영업한 기록의 T까지 완료 개월 평균을 내림. 세부 업종별 제공. 폐업 수명과 구분 |
| 연도별 추이 | 각 연도 연초~T와 같은 월·일의 YTD. 최근 12개월이나 연간 총계와 다름. 검증된 인접 두 연도만 서술, 빈 연도 0 생성 없음 |
| 과거와 최신 상태 | T 영업 기록의 최신 open/closed/other와 이후 폐업을 별도 보존. 본문은 T 이후 사건을 당시 사건으로 사용하지 않음 |
| 미확보 항목 | 공식 상권 적용 기준·공식 위험도 수치·매출·생활인구는 계속 미제공. 프랜차이즈 목록 일치는 실제 계약/과거 소속 증거가 아님 |

실제 서울 마포구 양화로45·카페500m·2025-11 조회는 T=2025-11-30, 원천 기준일=2026-11-08이다. T 영업 기록70건·최근 개업10/폐업11·평균63개월, 참고 폐업률11/81=13.6%다. 분모81은 T 점포70건과 정의가 다르므로 맞춰 바꾸지 않는다. 서울 비교13.0/84.3/58.4와 지역13.6/94.1/56.3의 차이는 각각+0.6/+9.8/-2.1%p다. YTD는2025-01-01~11-30 개업8/폐업11로 최근12개월 개업10과 다르며 정상이다. 최초 f515a49 기준의 건물 전체76건은 이후 #128 이름 제외 정책을 통합한 동일 조건 재검증에서 분석 대상75건이 됐다. 이 건수와 이후 폐업11건은 내부 evidence에만 보존하며 본문에 넣지 않았다. 선택 업종 카페 지표는 동일했고 최신 정책의 전파·새 문단·모바일/오류 동작도 실제 DB/Gemini와 브라우저로 다시 확인했다.

확인되지 않은 원천 한계는 유지한다. 수집 완료일null을 검증일로 채우지 않으며 지위승계·과거 재구성·공식 경계/통계 적용·프랜차이즈 계약 여부를 이번 개편으로 확정하지 않는다.

## 화면과 검증

AI 제목 오른쪽 정보 버튼은 클릭·외부 클릭·Esc·포커스 이탈로 제어하고 닫기 후 트리거에 포커스를 돌린다. 확보 자료/제외 자료/공통 한계와 요청별 결측을 팝오버에 표시한다. 화면 본문과 진단서에서 기존 번호형 구역·근거 칩·건물 총건수 나열을 제거한다. 조건 요약에는 주소·업종·반경·T·면적·가맹·두 unknown 조건·원천 기준일을 표시한다.

FE 캐시 키는 조회 조건·주소·건물·상세 위치·본문 버전을 포함하며 화면과 진단서가 공유한다. 조건 변경 시 컴포넌트가 새로 생성되고 이전 요청을 취소한다. 자동 AI 요청/재시도는 추가하지 않는다. 기존 오류·로딩과 지표 독립 처리를 유지한다. 모바일에서는 기존 데스크톱 디자인을 유지하면서 단계 탐색과 지표 배치를 좁은 화면에 맞춘다.

검증 증빙은 사용자 전용 `SpotON-private-backups/ai-narrative-20261114`에 보관한다. 실제 DB·Gemini 응답과 desktop1440/mobile390·360에서 본문4문단·팝오버·Esc/포커스/외부 클릭·가로 넘침 없음·조건 변경 후 이전 결과 제거·자동 POST 없음·모의503에도 지표 보존을 확인했다. 실제 DB는 읽기 전용으로 사용하며 통합 검사는 별도 임시 PostGIS에서 수행한다. 키·공급자 원문·원천 덤프는 저장소에 넣지 않는다.

최신 develop 통합 후 일반1,733건·strict mypy160파일·ruff/format을 통과했다. 신규 문단 검사15건에는 빈 선택·빈 모집단·다른 흐름/조작 ID·%p·분모 보존·YTD·미래 연도/기간 오류·건물 총건수 배제를 포함한다. FE는14파일108개와 lint/build를 통과했다. 통합 전 전체 PostGIS263건 및 선택 필수화 후 핵심31건의 로컬 검증과 최신 develop을 합친 PR의 전체 통합 CI를 구분한다.
