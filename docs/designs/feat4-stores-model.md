## 2. 모델 설계

### 2.1 파일과 메타데이터 로딩

- `app/models/store.py`에 `Store(Base)`를 정의하고 `__tablename__ = "stores"`로 둔다.
- `app/models/__init__.py`에서 `Store`를 `__all__`에 넣어 명시적으로 export한다.
- `migrations/env.py`는 `import app.models  # noqa: F401`로 모델 패키지를 부작용 import한 뒤 `target_metadata = Base.metadata`를 사용한다. `Store.metadata`는 같은 객체지만, 이후 모델이 늘어날 때 "패키지 import로 전체 모델 등록" 의도가 흐려지므로 쓰지 않는다. online·offline 경로 모두 같은 `target_metadata`를 쓴다.
- `Base.metadata`의 기존 naming convention을 유지한다. 최종 제약조건 이름은 2.4의 이름 표를 기준으로 하며, 구현 전에 기존 convention이 그 이름을 만드는지 확인한다(이중 접두사 `ck_stores_ck_stores_...` 금지).
- 의존성 전제: GeoAlchemy2가 SQLAlchemy 2.1을 공식 지원하는 버전으로 고정돼 있어야 한다. 의존성 목록에 없으면 커밋 2에서 의존성·lock 파일만 함께 추가한다. 지원 버전이 없거나 호환 오류가 나면 5.2 중단 조건을 따른다.
- Python 타입 힌트(mypy 대상): `id: Mapped[int]`, NOT NULL 문자열 `Mapped[str]`, nullable 컬럼 `Mapped[X | None]`, `Numeric`은 `Decimal`, `Date`는 `datetime.date`, `DateTime`은 `datetime.datetime`, `batch_id`는 `uuid.UUID`, `geom`은 `Mapped[WKBElement | WKTElement | None]`(읽기 `WKBElement`, 쓰기 `WKTElement`/`WKBElement`). GeoAlchemy2 타입 정보 부족으로 mypy가 실패하면 해당 모듈 한정 `ignore_missing_imports` override만 허용하고 7절에 기록한다.

### 2.2 식별자와 중복 기준

- 내부 참조용 `id BIGINT GENERATED BY DEFAULT AS IDENTITY`를 단일 PK로 둔다. 모델·migration 모두 `sa.Identity(always=False)`를 명시해 SERIAL/시퀀스 기본값으로 바뀌지 않게 한다. `BY DEFAULT`는 BE-08 재적재·복구 시 id 지정 insert를 막지 않기 위한 선택이다.
- `license_no`는 원천 안의 관리번호이고 원천 간 충돌 가능성이 있으므로 `(source, license_no)` UNIQUE를 둔다. 이 UNIQUE가 BE-08 upsert의 `ON CONFLICT (source, license_no)` 대상이며, 두 컬럼 모두 NOT NULL이라 NULL 중복 우회가 생기지 않는다.
- 원자료가 없는 상태에서 `license_no` 단독 PK, 상태·업종·`source` enum/CHECK, 브랜드 FK를 확정하지 않는다. `source` 허용값(예: 원천 데이터셋 코드)도 BE-08에서 정한다.

### 2.3 컬럼

컬럼 순서는 아래 표 순서를 모델·migration에 동일하게 적용한다. "기본값" 열에 없는 컬럼은 Python `default`·`server_default`를 두지 않는다.

| 구분 | 컬럼 | SQLAlchemy 타입 → PostgreSQL 타입 | null 정책 | 기본값 |
|---|---|---|---|---|
| 내부 식별 | `id` | BigInteger + `Identity(always=False)` → `bigint` identity | NOT NULL, PK | identity |
| 식별·원천 | `license_no`, `source` | String(64), String(32) → `varchar` | NOT NULL | 없음 |
| 식별·원천 | `gu_code`, `name` | String(10), String(255) | nullable | 없음 |
| 위치 | `address_road`, `address_jibun` | Text | nullable | 없음 |
| 위치 | `building_key`, `floor_unit`, `location_level` | String(255), String(100), String(32) | nullable | 없음 |
| 영업 | `open_date`, `close_date` | Date | nullable | 없음 |
| 영업 | `status`, `status_code`, `bzstat_nm` | String(32), String(32), String(100) | nullable | 없음 |
| 업종·규모 | `category`, `sub_category`, `seoul_induty_cd` | String(32) | nullable | 없음 |
| 업종·규모 | `area_m2` | Numeric(12, 2) | nullable | 없음 |
| 정제 좌표 | `lat`, `lng` | Numeric(10, 7) | nullable | 없음 |
| 공간 좌표 | `geom` | `Geometry(geometry_type="POINT", srid=4326, spatial_index=False)` → `geometry(Point,4326)` | nullable | 없음 |
| 원본 좌표 | `raw_x`, `raw_y` | Text | nullable | 없음 |
| 원본 좌표 | `raw_crs` | String(64) | nullable | 없음 |
| 좌표 판정 | `coord_source` | String(32) | nullable | 없음 |
| 좌표 판정 | `coord_flag` | Text | nullable | 없음 |
| 정제 판정 | `date_flag` | Text | nullable | 없음 |
| 정제 판정 | `is_temporary`, `category_review_flag` | Boolean | nullable | 없음 |
| 브랜드 | `is_franchise` | Boolean | nullable | 없음 |
| 브랜드 | `brand_id` | BigInteger | nullable, FK 없음 | 없음 |
| 이력 | `deleted_at` | DateTime(timezone=True) → `timestamptz` | nullable | 없음 |
| 이력 | `updated_at` | DateTime(timezone=True) → `timestamptz` | NOT NULL | `server_default=sa.text("now()")` |
| 이력 | `batch_id` | `sqlalchemy.dialects.postgresql.UUID(as_uuid=True)` → `uuid` | nullable | 없음 |

- `raw_x`, `raw_y`는 `Y=3,160` 같은 오류 표현까지 원문 그대로 보존하도록 숫자형으로 강제하지 않는다. `raw_crs`는 원천이 밝힌 좌표계 표기를 그대로 담으며 SRID 정수로 강제하지 않는다.
- `lat`, `lng`, `geom`은 **정제 결과**다. 변환·검증에 실패한 행은 세 컬럼을 NULL로 두고 `raw_x/raw_y/raw_crs`와 `coord_flag`로 원본과 사유를 보존한다. 따라서 위·경도 CHECK(2.4)가 원본 보존을 방해하지 않는다. `geom`의 축 순서는 PostGIS 관례대로 `POINT(lng lat)`(X=경도, Y=위도)다.
- `Numeric(10, 7)`은 정수부 3자리라 경도 ±180을 담을 수 있다. 범위를 크게 벗어난 값은 CHECK 이전에 numeric overflow로 거부되므로, ETL은 범위 밖 정제 좌표를 넣지 말고 NULL+flag로 처리한다.
- `is_temporary`, `category_review_flag`, `is_franchise`는 미확인을 `false`로 바꾸지 않도록 nullable Boolean으로 두고 `default=False`/`server_default`를 두지 않는다.
- `date_flag`, `coord_flag`는 원자료 검증 전이므로 DB enum/check를 두지 않는다. 복수 오류를 어떤 구분자·형식으로 담을지 BE-08에서 확정하기 전에 길이 제한으로 잘리지 않도록 `Text`로 둔다(PostgreSQL에서 `text`와 `varchar(n)`의 저장·성능 차이는 없다).
- 날짜 보존 의미: `open_date`, `close_date`는 **파싱 가능한** 날짜를 이상 여부와 무관하게 그대로 저장한다(1960년 이전, 미래, 개업>폐업 역전 포함). 날짜로 파싱할 수 없는 원문(예: `00000000`, 존재하지 않는 월·일)은 Date에 담을 수 없으므로 NULL+`date_flag`로 처리한다. 파싱 불가 원문 문자열 자체를 별도 컬럼에 보존할지는 원자료 확인 후 BE-08에서 결정한다(6절 보류 사항).
- `updated_at`은 `timezone=True`, `server_default=now()`로 insert 시각을 기록한다. ORM `onupdate`는 `ON CONFLICT DO UPDATE`에 적용되지 않으므로 이번에 두지 않고, ETL upsert 갱신 시각은 BE-08에서 `set_`에 명시한다. DB trigger도 이번 범위에 추가하지 않는다.
- `created_at` 등 작업계획 표에 없는 컬럼은 이번에 추가하지 않는다.
- 개인정보·연락처·대표자명·원천 전체 JSON 컬럼은 만들지 않는다.

### 2.4 제약조건과 인덱스

최종 DB 객체 이름은 다음으로 고정한다. 모델에서는 기존 naming convention이 아래 이름을 만들도록 짧은 이름 또는 `sqlalchemy.sql.elements.conv`/완성 이름을 쓰고, migration에서는 `op.f("<최종 이름>")`으로 그대로 지정한다. Alembic `op`의 MetaData에는 naming convention이 적용되지 않으므로 migration에서 이름을 생략하면 `stores_pkey` 같은 PostgreSQL 기본 이름이 생겨 모델과 어긋난다.

| 종류 | 이름 | 정의 |
|---|---|---|
| PK | `pk_stores` | `(id)` |
| UNIQUE | `uq_stores_source_license_no` | `(source, license_no)` |
| CHECK | `ck_stores_lat_range` | `lat IS NULL OR lat BETWEEN -90 AND 90` |
| CHECK | `ck_stores_lng_range` | `lng IS NULL OR lng BETWEEN -180 AND 180` |
| INDEX | `ix_stores_geom_gist` | `geom`, `USING gist` (`postgresql_using="gist"`) |
| INDEX | `ix_stores_building_key` | `building_key` (btree) |
| INDEX | `ix_stores_category_status` | `(category, status)` 순서 고정 (btree) |
| INDEX | `ix_stores_open_date` | `open_date` (btree) |
| INDEX | `ix_stores_close_date` | `close_date` (btree) |

- 기존 convention 결과가 위 이름과 다르면 이름을 임의로 바꾸지 말고, 기존 convention 결과로 통일할지 결정해 모델·migration·테스트를 같은 이름으로 맞추고 7절에 기록한다.
- 인덱스는 모델 `__table_args__`의 `Index(...)`로만 정의하고 컬럼의 `index=True`는 쓰지 않는다(자동 이름 `ix_stores_<col>` 중복 방지). UNIQUE 제약이 만드는 내부 인덱스 외에 `(source, license_no)` 인덱스를 따로 만들지 않는다.
- `geom`은 모델·migration 양쪽 모두 `spatial_index=False`로 둔다. GeoAlchemy2는 `op.create_table`에서도 테이블 생성 이벤트로 자동 GIST 인덱스(`idx_stores_geom`)를 만들 수 있으므로, 한쪽만 False면 GIST 인덱스가 2개 생긴다.
- 날짜 역전·1960년 이전·미래 날짜와 음수 면적은 원본 보존·플래그 대상이므로 DB CHECK로 거부하지 않는다. 서울 범위(bbox) CHECK도 두지 않는다.
- `lat/lng/geom`의 상호 일치는 ETL 좌표 검증 책임이며 이번 모델에서 trigger나 생성 컬럼을 두지 않는다.
- `gu_code`, `brand_id`, `deleted_at` 인덱스와 `deleted_at IS NULL` 부분 인덱스, `geom::geography` 함수 인덱스는 미래 API 조회 패턴이 확정되지 않았으므로 이번에 만들지 않는다(6절 보류 사항). 인덱스 추가는 이후 별도 migration으로 비파괴적으로 가능하다.

## 3. 마이그레이션

- `migrations/versions/0002_create_stores.py`
- `revision = "0002"`, `down_revision = "0001"`, `branch_labels = None`, `depends_on = None`. 0002는 `0001`이 PostGIS 확장을 만든다는 전제에 의존하며, 0002에서 `CREATE EXTENSION`을 반복하지 않는다.
- migration은 `app.models`를 import하지 않는다(이후 모델 변경이 과거 revision을 바꾸지 않도록). `import sqlalchemy as sa`, `from alembic import op`, `from geoalchemy2 import Geometry`, `from sqlalchemy.dialects import postgresql`만 사용한다.
- upgrade 순서:
  1. `op.create_table("stores", ...)` — 2.3 표의 컬럼 순서·타입·nullability·`sa.Identity(always=False)`·`server_default=sa.text("now()")`, `Geometry(geometry_type="POINT", srid=4326, spatial_index=False)`, 그리고 `sa.PrimaryKeyConstraint("id", name=op.f("pk_stores"))`, `sa.UniqueConstraint("source", "license_no", name=op.f("uq_stores_source_license_no"))`, 두 `sa.CheckConstraint(..., name=op.f(...))`를 테이블 정의 안에 포함한다.
  2. `op.create_index(op.f("ix_stores_geom_gist"), "stores", ["geom"], postgresql_using="gist")`
  3. 나머지 btree 인덱스 4개를 2.4 표의 이름·컬럼 순서로 `op.create_index`한다.
- downgrade는 `op.drop_table("stores")` 하나로 테이블과 소속 인덱스·제약조건을 함께 제거한다. PostGIS 확장과 `0001` 객체는 유지한다. GeoAlchemy2 drop 이벤트가 `DropGeometryColumn` 같은 추가 SQL을 내지 않는지 offline SQL로 확인한다.
- 타입·기본값·제약조건·인덱스 이름을 모델과 migration에 각각 명시해 autogenerate에 의존하지 않는다. 모델과 migration의 불일치는 4절의 공통 기대 명세 테스트로 잡는다.
- offline `alembic upgrade head --sql`과 `alembic downgrade 0002:0001 --sql`이 DB 연결·비밀값 없이 생성돼야 한다. offline SQL에서 geometry 타입은 `geometry(POINT,4326)`로 렌더링돼야 한다.

## 4. 검증 설계

### 4.1 단위·offline 검사

공통 기대 명세: 2.3·2.4 표를 테스트 코드 한 곳(예: `tests/stores_schema_spec.py`)에 컬럼명→(PostgreSQL `format_type` 문자열, nullable, 기본값 유무)과 제약조건·인덱스 이름→정의로 한 번만 적는다. 단위 테스트는 이 명세와 **모델**을, 통합 테스트는 같은 명세와 **실제 migration 결과 DB**를 비교한다. 그래서 모델과 migration이 서로 다르게 구현되면 둘 중 하나가 반드시 실패한다.

`tests/test_store_model.py`에서 다음을 검사한다.

- 컬럼 집합이 명세와 **정확히 같음**(누락·추가 모두 실패), 컬럼 순서, 타입 클래스, 길이·precision/scale, nullability
- `id`가 유일한 PK이고 `Identity(always=False)`를 가지며, `CreateTable(Store.__table__).compile(dialect=postgresql.dialect())` 결과에 `GENERATED BY DEFAULT AS IDENTITY`와 `geometry(POINT,4326)`이 포함됨
- 제약조건 이름 4개(`pk_stores`, `uq_stores_source_license_no`, `ck_stores_lat_range`, `ck_stores_lng_range`)가 naming convention 적용 후 최종 이름으로 존재하고 UNIQUE 컬럼 순서가 `(source, license_no)`임
- `geom` 타입이 `geometry_type == "POINT"`, `srid == 4326`, `spatial_index is False`
- `Store.__table__.indexes`가 정확히 5개이고 이름·컬럼 순서가 명세와 같으며, `ix_stores_geom_gist`만 `dialect_options["postgresql"]["using"] == "gist"`
- nullable Boolean 3개에 `default`·`server_default`가 없음, `raw_x/raw_y` Text, `coord_flag/date_flag` Text, `deleted_at/updated_at` `timezone=True`, `updated_at`만 server default 보유, `batch_id` UUID `as_uuid=True`, `brand_id`에 FK 없음(`Store.__table__.foreign_keys` 비어 있음)
- 대표자명·전화번호·원본 전체 JSON 같은 금지 컬럼 부재(JSON/JSONB 타입 컬럼 0개 포함)
- `Store.metadata is Base.metadata`, `import app.models` 후 `"stores" in Base.metadata.tables`

`tests/test_migrations.py`를 보완해 다음을 검사한다.

- offline upgrade SQL에 `CREATE TABLE stores`, `geometry(POINT,4326)`, `GENERATED BY DEFAULT AS IDENTITY`, 4개 제약조건 이름, 5개 인덱스 이름, `USING gist`가 포함되고, GeoAlchemy2 자동 인덱스 이름 `idx_stores_geom`과 `CREATE EXTENSION`(0002 구간)은 포함되지 않음
- `0002:0001` downgrade SQL은 `DROP TABLE stores`를 포함하고 `DROP EXTENSION`·`DropGeometryColumn`은 포함하지 않음
- `migrations/env.py`가 `Base.metadata`를 target으로 쓰고 `app.models`를 import하는지: env.py는 Alembic context 밖에서 import할 수 없으므로 소스 AST에서 `import app.models`(또는 `from app import models`)와 `target_metadata = Base.metadata` 대입을 확인한다. 0002 migration 소스가 `app.models`를 import하지 않는지도 같은 방식으로 확인한다.

### 4.2 실제 PostGIS 통합 검사

`tests/integration/test_store_migration.py`를 추가하고 기존 안전한 `temporary_database` fixture를 재사용한다.

1. `upgrade head` 후 revision `0002`. `information_schema.columns`와 `format_type(atttypid, atttypmod)`로 컬럼 집합·순서·타입(`character varying(64)`, `numeric(10,7)`, `geometry(Point,4326)`, `timestamp with time zone`, `uuid` 등)·nullability·기본값을 공통 기대 명세와 **정확히** 비교한다. `id`는 `is_identity='YES'`, `identity_generation='BY DEFAULT'`.
2. `pg_constraint`에서 4개 제약조건 이름·종류를 확인한다. `geometry_columns`에서 `stores.geom`이 `type='POINT'`, `srid=4326`인지 확인한다.
3. `pg_indexes`/`pg_index`+`pg_am`에서 stores 인덱스가 PK·UNIQUE 내부 인덱스 + 명세 5개뿐이고(`idx_stores_geom` 없음), `ix_stores_geom_gist`의 access method가 `gist`, 나머지는 `btree`이며 `ix_stores_category_status` 컬럼 순서가 `(category, status)`인지 확인한다.
4. 제약 위반은 각각 별도 트랜잭션(또는 savepoint)에서 실행하고 SQLSTATE·제약조건 이름까지 확인한다.
   - 같은 `(source, license_no)` 재insert → `unique_violation`(`uq_stores_source_license_no`). 같은 `license_no`·다른 `source`는 허용.
   - `lat=91`, `lat=-91`, `lng=181`, `lng=-181` → `check_violation`(해당 CHECK 이름). 경계값 `±90`, `±180`과 NULL은 허용.
   - `source=NULL` 또는 `license_no=NULL` → `not_null_violation`.
   - `geom`에 `LINESTRING` 또는 SRID 5179/0 점 → geometry typmod 위반으로 거부.
5. ORM으로 정상 행을 insert/read한다: `is_temporary`·`category_review_flag`·`is_franchise` 미지정 시 NULL로 남고(False 아님), `raw_x="X=127,0"`, `raw_y="Y=3,160"` 원문 보존, `open_date=date(1950,1,1)`·미래 날짜·`open_date > close_date` 역전·`area_m2=-1`이 거부되지 않고 그대로 저장, `updated_at` 자동 설정·tz-aware, `batch_id`가 `uuid.UUID`로 왕복, `geom=WKTElement("POINT(126.9780 37.5665)", srid=4326)` 저장 후 `ST_SRID(geom)=4326`, `GeometryType(geom)='POINT'`, `ST_X(geom)=126.978`(경도), `ST_Y(geom)=37.5665`(위도).
6. `downgrade 0001` 후 stores 없음, `pg_extension`에 `postgis` 유지, revision `0001` 확인
7. 다시 `upgrade head`가 성공하고 1~3 스키마 검사를 재실행해 동일함을 확인

통합 테스트는 CI가 생성한 `spoton_it_` 임시 DB에서만 실행한다. 실제 개발 DB·SQLite·mock 결과로 대체하지 않는다. 기존 `temporary_database` fixture의 skip 정책(접속 정보 없을 때 skip 여부)을 구현 전에 확인한다. 로컬에서는 skip될 수 있으나, CI `postgis-integration` job에서는 skip이 1건이라도 있으면 완료 조건 4 미충족으로 본다(`pytest -rs` 출력 또는 리포트의 skipped=0을 7절에 기록).

### 4.3 실제 개발 DB 없이 진행 가능한 범위

- 단위·offline 검사(4.1)는 DB·네트워크·비밀값 없이 로컬에서 끝난다.
- 실제 PostgreSQL 17/PostGIS 동작(4.2)은 CI의 임시 DB에서 검증한다. 로컬에 PostGIS가 없으면 4.2는 CI 결과로만 판정하고, 로컬 결과를 근거로 통과를 주장하지 않는다.
- 원천 파일·개발 DB 데이터는 이번 범위에서 필요하지 않다. 테스트 데이터는 위 합성 행으로 충분하다.

## 6. Claude Code 검토 기록

검토 방식: Claude Code가 이 파일만 Read·Edit했다. 코드·원본 작업계획·다른 문서·Git·셸 명령은 사용하지 않았다. 따라서 "작업계획과 일치" 여부는 이 문서 1·2절에 옮겨진 범위를 기준으로만 판단했고, 원본 작업계획과의 최종 대조는 Codex 단계(완료 조건 2)에서 한다. 기존 코드(`Base` naming convention, `0001`, `temporary_database`)는 직접 보지 못했으므로 관련 전제는 5.2-4 중단 조건으로 남겼다.

### 6.1 수정 사항과 이유

| # | 위치 | 수정 | 이유 |
|---|---|---|---|
| 1 | 2.1 | `env.py`는 `import app.models` + `target_metadata = Base.metadata` | `Store.metadata`는 같은 객체지만 모델별 import에 묶이면 이후 모델 누락 위험. 패키지 import 하나로 등록 경로를 고정 |
| 2 | 2.1 | GeoAlchemy2의 SQLAlchemy 2.1 호환 전제, Python 타입 힌트, mypy override 허용 범위 명시 | mypy 대상에 `app`·`migrations`가 포함되어 타입 결정이 구현 성패에 직결 |
| 3 | 2.2 | `Identity(always=False)` 명시, UNIQUE가 BE-08 `ON CONFLICT` 대상임을 명시, `source` enum 미확정 추가 | SERIAL로의 우발적 변경 방지, ETL 재적재 시 id 지정 가능성 보존 |
| 4 | 2.3 | `coord_flag`, `date_flag`를 String(64) → Text | 복수 오류 표현 방식이 BE-08 미결이라 64자 제한이 ETL에서 잘림/실패를 일으킬 수 있음. Text는 이후 좁히기보다 안전하고 PostgreSQL 성능 차이 없음 |
| 5 | 2.3 | 기본값 열 추가, Boolean 3개 default 금지 명시 | 미확인 NULL이 ORM/서버 기본값으로 False가 되는 구현 오류 방지 |
| 6 | 2.3 | 정제 좌표(lat/lng/geom) vs 원본 좌표 의미, 축 순서 `POINT(lng lat)`, Numeric overflow 주의 | CHECK가 원본 보존을 막지 않는다는 근거 명확화, 위경도 뒤바뀜 방지 |
| 7 | 2.3 | 날짜 보존 의미 정의: 파싱 가능한 이상 날짜는 그대로, 파싱 불가는 NULL+`date_flag` | Date 타입은 파싱 불가 원문을 담을 수 없어 "이상 날짜 보존" 범위를 명확히 해야 함 |
| 8 | 2.3 | `updated_at`에 ORM `onupdate`를 두지 않는 이유 명시 | `ON CONFLICT DO UPDATE`에는 onupdate가 적용되지 않아 오해 소지 |
| 9 | 2.4 | 제약조건·인덱스 최종 이름 표, migration에서 `op.f()`로 이름 지정 | Alembic `op`에는 naming convention이 없어 이름 생략 시 `stores_pkey` 등으로 모델과 불일치. 이중 접두사도 방지 |
| 10 | 2.4/3 | `spatial_index=False`를 모델·migration 양쪽에 적용, 컬럼 `index=True` 금지 | GeoAlchemy2 테이블 생성 이벤트가 `op.create_table`에서도 자동 GIST(`idx_stores_geom`)를 만들어 중복 인덱스 발생 가능 |
| 11 | 3 | upgrade 순서, migration에서 `app.models` import 금지, `CREATE EXTENSION` 반복 금지, downgrade SQL 확인 항목 | 과거 revision 불변성, 0001과 책임 분리 |
| 12 | 4 | 공통 기대 명세로 모델·실DB를 각각 비교, 컬럼 집합 "정확히 같음" 검사 | 모델과 migration을 따로 손으로 쓰므로 drift를 잡을 장치가 필요. autogenerate `compare_metadata`는 geometry 타입 비교 오탐 가능성이 있어 catalog 비교를 택함 |
| 13 | 4.1 | env.py는 AST 검사로 확인 | env.py는 Alembic context 밖에서 import 불가 |
| 14 | 4.2 | SQLSTATE·제약 이름 확인, NOT NULL·geometry typmod 위반, 경계값, 이상 날짜·음수 면적 허용, `ST_X/ST_Y` 축 검사, 자동 인덱스 부재, 재upgrade 후 스키마 재검사 | 기존 안은 "거부되는지"만 봐서 잘못된 제약(예: 다른 이유로 실패)도 통과할 수 있었고, 보존 요구(이상 날짜·미확인 NULL)를 실제 DB에서 검증하지 않았음 |
| 15 | 4.2/4.3 | skip 정책 확인, CI skip=0 기록, 개발 DB 없이 가능한 범위 명시 | 완료 조건 4의 "skip 없이"를 확인 가능한 형태로 |
| 16 | 5 | 커밋 경계 규칙, 중단 조건 목록화, squash 후 SHA 변경 주의 | 기존 문서는 중단 조건이 1절에 산재 |

### 6.2 결정 사항

- PK는 `id` identity, 업무 키는 `(source, license_no)` UNIQUE로 유지한다.
- 상태·업종·`source`·flag 값에 enum/CHECK를 두지 않고, `brand_id`에 FK를 두지 않는다.
- DB CHECK는 정제 위·경도 범위 2개만 둔다. 날짜·면적·서울 bbox CHECK는 두지 않는다.
- 인덱스는 작업계획의 5개만 만든다.
- 모델·migration 불일치 검출은 공통 기대 명세 + 실제 PostGIS catalog 비교로 한다.
- 이번 작업은 실제 개발 DB 없이 단위·offline·CI 임시 DB만으로 완료 가능하다.

### 6.3 남은 보류 사항 (BE-08 또는 API 작업에서 원자료·조회 패턴 확인 후 결정)

1. `date_flag`·`coord_flag` 코드 목록과 복수 오류 표현 형식(구분자 문자열 vs 배열), 필요 시 CHECK 추가
2. 파싱 불가 날짜 원문(`raw_open_date` 등) 보존 컬럼 필요 여부 — 필요하면 별도 migration으로 추가
3. `status`·`category`·`sub_category`·`source` 허용값과 enum/CHECK 여부, 각 String 길이의 원자료 기준 적정성(`category` 32자 등)
4. `area_m2`의 소수 자릿수(원천이 소수 3자리 이상이면 반올림 손실) 확인
5. `brand_id` FK 및 brands 테이블 설계
6. 미래 API용 인덱스: `gu_code`, `brand_id`, `deleted_at IS NULL` 부분 인덱스, 반경 검색을 `geography`로 할 경우 `(geom::geography)` 함수 GIST 인덱스 또는 투영 좌표계 사용 여부
7. `updated_at` 갱신 방식(upsert `set_` 명시)과 `created_at` 필요 여부
8. Alembic autogenerate를 쓸 경우 PostGIS 시스템 테이블 제외(`include_object`)와 GeoAlchemy2 `alembic_helpers` 적용 — 이번 범위에서는 autogenerate를 쓰지 않으므로 보류
