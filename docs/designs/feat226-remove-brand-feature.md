# 브랜드·프랜차이즈 기능 제거 설계

2026-11-17 사용자 요청. 설계 검토와 구현 재검토는 Codex가 수행한다.

## 의존성 검토 및 삭제 범위

브랜드 v2 라우터가 일반 주변 점포·시점·상권 활동·위험도 및 위치 이력 API도 제공한다. 라우터 전체를 삭제하지 않고 일반 분석 라우터로 분리한다. v3 주소 통합 이력도 브랜드 후처리에 의존하므로 점포 변환만 남긴다.

- 제거: 브랜드 상태 API, 가맹/체인 필터 입력·응답 필드, 브랜드 목록/소속/운영 형태 후처리, 세대 비교·판정 상태/카운트, 브랜드 SQL 및 AI 문맥·프롬프트·캐시 요소.
- FE 제거: 입력/조건 바/팝업의 소속 선택, 표/지도/상세/AI/인쇄의 브랜드 표시, 브랜드 상태 요청·경고·관련 주의사항 및 전용 타입/유틸리티/목업.
- 점포 상세의 브랜드 소속 칸은 실제 조회 응답의 기준 시점으로 교체한다. 주변·시점은 data.as_of, 위치 이력은 meta.as_of를 사용하며 없으면 정보 없음이다. 오늘이나 개업일을 대신 쓰지 않는다.
- 보존: 주소 검증 및 v3 도로명·지번 통합 이력, 업종/세부업종·반경·면적·기준월, 영업 기간·상태·출처·점포 복합 키, 매출 상권합산/상위3 산식, 생활인구/주야간 비교, AI 숫자 검증과 출처 일관성, 요청 큐/취소/PDF.
- v1/v2 일반 분석 URL은 유지한다. 제거된 브랜드 필터는 서버에서 422로 거부하며 이전 FE 링크의 브랜드 조건은 버리고 나머지 조건은 복원한다. 브랜드 상태 URL은 404이다.
- 과거 마이그레이션/원본 DB 컬럼·보관 데이터는 변경하지 않는다. 기존 마이그레이션을 지우면 신규 구축/0014 검증에 영향이 있으므로 비활성 보관한다. 운영 원자료 삭제·DB 다운그레이드는 수행하지 않는다.

## 검토 기준

동일한 전체 점포 조건에서 주변/시점/활동/위험도 수치와 이력 집합을 유지한다. API 명세·응답·LLM 입력에 브랜드 필드가 없고 실행 SQL이 브랜드 테이블을 조회하지 않아야 한다. FE는 브랜드 상태 API를 호출하지 않으며 기준일을 모든 점포 상세에 전달한다. 기존 브랜드 전용 테스트는 제거된 계약의 테스트이므로 삭제/교체하고 일반 기능 회귀는 유지한다.

## Codex 사전 검토

파일명 chains만 보고 라우터 전체를 삭제하는 방안은 기각했다. 기존 일반 분석 서비스에서 판정 의존성을 제거하고 공개 v2 DTO와 AI의 생활인구 연결은 유지한다. DB 모델/이전 ETL 보관 여부와 공개 실행 경로를 구분해 원자료 보존과 런타임 경량화를 함께 충족한다.

## Codex 구현 후 독립 재검토

- 일반 조회를 제공하는 라우터/DTO/AI 모듈을 analysis_v2/interpret_v2/context_v2로 분리했다. 브랜드 상태 라우트와 수집·판정·공개·유지보수 CLI는 삭제했다.
- 주변·시점·활동·Risk·기존 이력/v3 주소 이력은 원래 업종·면적·거리·날짜·복합 식별 규칙을 유지한다. 브랜드 불명 기록을 버리는 조건도 없다.
- 매출/상권 합산·상위3·전체생활인구·주야간 산술과 자료 선택 모듈, 모든 DB 모델/마이그레이션은 변경하지 않았다. 공식 점포 통계 원천의 total/general/franchise 개수는 원본 정합성 확인에만 남기며 소속 필터·개별 점포 판정으로 사용하지 않는다.
- AI는 v1 prompt v10, v2 analysis-risk-interpret-v3로 구분하고 프롬프트 지문/선택 캐시 규칙을 새로 분리했다. 브랜드 문맥·주의사항은 제거하고 같은 날짜/원천/모집단·숫자·생활인구 검증은 유지한다.
- 운영 로그의 과거 브랜드 source/path 허용 목록은 역사 로그 재생·백업 호환에 필요하므로 보존했다. 이 목록은 API 등록이나 브랜드 조회를 실행하지 않는다.
- 기존 브랜드 전용 테스트/CLI 테스트는 삭제했다. 일반 이력·면적·날짜·API/AI 회귀는 남기고 제거된 필드 기대값을 새 계약으로 바꿨다. 신규 테스트는 제거된 API404/필터422/DB 미접속 및 일반v1/v2의 동일 결과와 브랜드 테이블SQL0을 확인한다.
- FE 상세 기준 시점은 nearby/snapshot의 data.as_of 및 이력 meta.as_of다. 지도 단일·묶음 정보창, 표, PDF 공유 컴포넌트 모두 같은 날짜를 전달하고 null은 정보 없음이다.

## 전달/적용 경계

기능 제거는 FE/BE의 함께 적용할 변경이다. 운영 DB 삭제·다운그레이드는 필요 없다. 코드 통합과 공개 배포의 완료 여부는 실제 PR/배포 기록을 구분한다. 이전 FE는 제거된 브랜드 필터를 전송하므로 새 BE만 먼저 공개하면422가 발생한다. 공개 전환 때에는 브랜드 필터를 보내지 않는 새 FE를 먼저 반영한 뒤 새 BE를 반영해야 하며, 전환 구간의 AI는 prompt 불일치 시 기존 검증에 따라 재조회 안내를 유지한다. 이전 FE로만 되돌리면 새 BE와 호환되지 않으므로 양쪽을 함께 복구한다.
